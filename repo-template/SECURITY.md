# SECURITY и обращение к сопровождающим

## Ошибка в нормативном требовании (P1)

Если вы нашли расхождение между текстом в `md/` и официальным источником — **это не баг кода, это риск для безопасности**. Откройте issue «Ошибка в документе» с пометкой `p1-requirement`:

- `doc_id`, номер пункта;
- что в корпусе / что в официальном источнике (цитата + ссылка);
- характер расхождения: числовое значение, единицы, знак требования («должно» vs «следует»), пропущенный абзац.

Документ немедленно получает `status: under_review` в `overrides/`, изымается из «доверенного» индекса и возвращается после исправления и верификации.

## Уязвимости в инструментах

Конвертер обрабатывает недоверенные файлы (OOXML — это zip + XML: возможны zip-бомбы, XXE, path traversal в именах ассетов). Сообщения о проблемах в `tools/` — на `security@<домен>` (не в публичные issue).

Что уже учтено в конвейере: разбор XML без внешних сущностей, имена файлов ассетов генерируются из `doc_id` + счётчика (не из пути внутри архива), ограничение на размер ассета (`max_asset_mb`), запрет на исполнение содержимого документов.

## Претензии правообладателей (takedown)

`takedown@<домен>`. Порядок — в [`NOTICE.md`](NOTICE.md): изъятие из публичного доступа в течение 3 рабочих дней до выяснения обстоятельств.

## Что не является инцидентом

- низкий `conversion.confidence` у свежеимпортированного документа — это штатная очередь доработки (`catalog/INDEX.md` → «Требует внимания»);
- отсутствие документа в корпусе — это заявка на добавление (`inbox/`).

## Сопровождающие

| роль | зона ответственности |
|---|---|
| владелец корпуса | приоритеты импорта, статусы, спорные документы |
| владелец конвертера | `tools/`, golden-тесты, регрессии |
| верификаторы | вычитка, `verified: true`, качество таблиц и формул |
| дежурный по takedown | претензии, удаление |
