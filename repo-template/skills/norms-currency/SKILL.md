# Актуальность нормативных документов

Отменённая норма, приведённая как действующая, — самая опасная ошибка в этой предметной области. Проверяй статус всегда.

## Порядок проверки

### 1. Статус в корпусе

```
norms.status("snip-2-01-07-85")
```

или без сервера:

```bash
jq 'select(.doc_id=="snip-2-01-07-85") | {designation,status,superseded_by,amendments,status_checked}' \
   catalog/catalog.jsonl
```

| `status` | что делать |
|---|---|
| `active` | можно цитировать, указав изменения |
| `superseded` | цитировать только для исторических объектов; дать замену из `superseded_by` |
| `draft` | «проект, не введён в действие» — не использовать для требований |
| `unknown` | **сверить с официальным реестром** до ответа |
| `rejected` | не использовать |

### 2. Свежесть сверки

Поле `status_checked` показывает, когда статус сверяли в последний раз. Если прошло больше 6 месяцев или документ критичен — сверь вручную:

- **СП, СП с изменениями** → реестр сводов правил ФАУ «ФЦС» Минстроя России;
- **ГОСТ, ГОСТ Р** → ФГИС СТ (protect.gost.ru / gost.ru);
- **приказы, постановления, технические регламенты** → pravo.gov.ru, docs.cntd.ru;
- **сметные нормативы** → ФРСН (реестр сметных нормативов Минстроя).

Результат сверки занеси в `overrides/<doc_id>.yaml` (`status`, `status_checked`) — это единственное место, где правится статус.

### 3. Изменения (Изм. № 1, № 2, …)

Изменения к СП и ГОСТ выходят постоянно и **меняют числовые требования**. Всегда:

- указывай их при цитировании: «СП 63.13330.2018 (с изм. № 1–3)»;
- проверяй, что в корпусе текст с учётом изменений (`amendments` во фронтмэттере + `source.sha256` оригинала);
- если в тексте есть сноска «В редакции изменения № 2» — она должна быть сохранена;
- если вопрос про объект, спроектированный в прошлом, — важна **редакция на дату**, а не текущая. Спроси дату или работай с исторической редакцией.

### 4. Переходные положения

При замене документа почти всегда есть переходный период (обычно 6–12 месяцев), в течение которого допускается применять старый документ. Проверяй:

- дату введения в действие нового документа (`in_force_since`);
- текст приказа об утверждении — в нём указаны переходные положения (они попадают в корпус как отдельный документ `kind: order` или в `overrides`);
- дату выдачи разрешения на строительство / дату договора — для действующих объектов часто применяется «старая» редакция.

### 5. Что отвечать пользователю

Обязательная строка в любом ответе, опирающемся на норматив:

```
Статус на 2026-10-16: действует (СП 63.13330.2018, с изм. № 1–3, введён 2018-08-01).
```

Если документ отменён:

```
⚠️ СНиП 2.01.07-85* утратил силу: с 2011 года применяется СП 20.13330.2016
«Нагрузки и воздействия» (действующая редакция — с изм. № 4). Приведённые ниже
значения даны по отменённому документу только для справки об историческом объекте.
```

Если статус неизвестен:

```
Статус документа в корпусе не сверен (status: unknown). Перед применением
проверьте актуальность в реестре ФАУ «ФЦС» / ФГИС СТ.
```

## Типовые ловушки

| ситуация | что делать |
|---|---|
| СНиП «со звёздочкой» (СНиП 2.01.07-85*) | звёздочка = с изменением; проверь, есть ли соответствующий СП |
| Документ «взамен» и «взамен в части» | при замене **в части** действуют оба документа — в разных частях |
| ГОСТ с тем же номером, но другим годом | это разные документы; старый обычно отменён, но на него могут ссылаться действующие СП |
| Межгосударственный ГОСТ и национальный ГОСТ Р | могут действовать параллельно; проверяй область применения каждого |
| СП из «перечня обязательных» | статус «действует» не равен «применим в вашем случае»: проверяй область применения (п. 1.1) |
| Документ приостановлен | отдельный статус, встречается у приказов; не путать с отменой |
