# Поиск в корпусе нормативов

## Порядок действий (соблюдай последовательность)

### Шаг 1. Понять, что спрашивают
Определи три вещи до поиска:
- **объект регулирования** (конструкция, материал, процесс, документация);
- **тип требуемого ответа** (числовое значение, процедура, запрет, определение, ссылка на методику);
- **контекст применения** (здание/сооружение, класс ответственности, условия эксплуатации, стадия проектирования).

Если контекст неизвестен, а от него зависит ответ — спроси, не угадывай.

### Шаг 2. Точный поиск (если в запросе есть обозначение или пункт)
Это самый надёжный канал — используй его всегда, когда возможно:

```
norms.get(doc_id="sp-63-13330-2018", clause="8.1.6")
# или без сервера:
grep -n "\^c8-1-6$" md/sp-63-13330-2018.md      # по идентификатору блока
grep -n "^\*\*8\.1\.6\*\*" md/sp-63-13330-2018.md   # по номеру пункта
```

Проверь статус документа до цитирования: `norms.status(doc_id)`.

### Шаг 3. Содержательный поиск
```
norms.search(
  query="минимальный защитный слой бетона рабочей арматуры плиты",
  kind=["sp"],            # сузь тип документа, если он очевиден
  status=["active"],      # ОБЯЗАТЕЛЬНО: не искать в отменённых
  k=10
)
```

Правила формулировки запроса:
- используй **терминологию нормативов**, а не разговорную: «защитный слой бетона», «класс по прочности на сжатие», «предельный прогиб», «анкеровка арматуры»;
- делай 2–3 запроса разными формулировками (синонимия в нормативах высокая: «прогиб» / «деформация», «армирование» / «конструирование»);
- числовые значения и марки («B25», «М300») ищи **ключевыми словами** (BM25), а не семантически.

### Шаг 4. Расширить контекст найденного
Найденный пункт почти никогда не самодостаточен. Обязательно подтяни:
1. **раздел и подраздел**, в которых он находится (`breadcrumb` чанка) — они задают область применения;
2. **примечания** к пункту (в нормативах примечание часто содержит исключение из требования);
3. **таблицы**, на которые ссылается пункт (`нормы вида «по таблице 8.1»`) — бери значения из `md/<doc_id>.tables.jsonl`, поле `grid`;
4. **«где»-блок** после формулы — без него формула непонятна;
5. **пункты других документов**, упомянутые в найденном (`references` во фронтмэттере).

### Шаг 5. Проверить применимость документа
Перед тем как давать ответ:
- `status == active`? если `superseded` — найди замену в `superseded_by`;
- `amendments` — учтены ли изменения? (в ответе указывай «с изм. № …»);
- распространяется ли документ на ваш объект (см. раздел «Область применения» — пункт 1.1);
- не противоречат ли требования разных документов друг другу в данном случае; при противоречии — покажи оба и скажи, что нужен выбор по более строгому/специальному.

## Что делать, если не нашлось

1. Переформулируй запрос (минимум 3 попытки с разной терминологией).
2. Поищи по смежным видам документов (`kind` без фильтра): требование может быть в ГОСТ на материал, а не в СП на конструкцию.
3. Проверь, есть ли документ в корпусе вообще: `grep -i "<тема>" catalog/INDEX.md`.
4. Если документа нет в корпусе — **так и скажи** и назови, какой документ, вероятно, содержит ответ. Не выдавай найденное в похожем документе за искомое.

## Чего делать нельзя

- цитировать документ со статусом `superseded` как действующий;
- интерполировать или экстраполировать значения из таблиц («для B27 возьмём среднее между B25 и B30») — нормативных значений для промежуточных классов нет;
- складывать требования из разных документов в одно «итоговое требование», не показывая источники;
- отвечать по непроверенному документу (`verified: false`) без оговорки.

## Инструменты

| инструмент | назначение |
|---|---|
| `norms.search(query, kind, status, topics, year_min, k)` | семантический + ключевой поиск по чанкам |
| `norms.get(doc_id, clause?)` | точный текст пункта/раздела + якорь + страница |
| `norms.status(doc_id)` | действует / отменён / чем заменён / изменения |
| `norms.tables(doc_id)` | нормализованные таблицы документа |
| `grep -rn "\^c8-1-6" md/` · `catalog/CLAUSES.md` | поиск и готовые ссылки без сервера |
| `catalog/catalog.jsonl` | что вообще есть в корпусе |
