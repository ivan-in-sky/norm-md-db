# Добавление документа в корпус

> Этот навык — для **публикационного репозитория** (inbox → PR). Полная версия
> цикла для рабочего vault (разведка актуальной редакции, скачивание,
> эталон-сверка, страницы, статусы) — `docs/10-local-agent.md` §3; различия
> только в именах папок (`md/`↔`документы/`, `overrides/`↔`правки/`,
> `sources/`↔`источники/`).

## Шаг 0. Проверить допустимость

Принимаются официальные нормативные документы: СП, СНиП, ГОСТ, ГОСТ Р, РД, МДС, ВСН, ТСН, НПБ, Пособия к СНиП, сметные нормативы, приказы об утверждении.

**Не принимаются** (см. `NOTICE.md`): СТО и внутренние документы организаций, документы с грифом, сканы из коммерческих справочных систем, файлы с водяными знаками.

Проверь дубликаты и редакции:

```bash
grep -i "<номер>" catalog/INDEX.md
jq -r 'select(.number|test("63.13330")) | .doc_id' catalog/catalog.jsonl
```

## Шаг 1. Положить источник

```bash
cp ~/Downloads/sp-63-13330-2018.docx inbox/
# оригиналы уходят в object storage, в Git — только запись в sources/inventory.csv
```

Заполни в `sources/inventory.csv` (16 колонок — полный справочник в `docs/10-local-agent.md` §2.3):

```
file,sha256,size_bytes,kind,doc_id,source_level,source_tier,text_layer,has_math_omml,has_images,tables_guess,origin_url,origin_date,fetched_from_sandbox,license_note,notes
sp-63-13330-2018.docx,3fa9c2…,1843200,docx,sp-63-13330-2018,B,commercial_sps_export,yes,yes,yes,43,https://…,2026-10-16,no,официальный документ (ГК РФ ст.1259 п.6),…
```

`source_level`: A — официальный XML/UZ, B — docx/нативный PDF с живым текстом, C — скан/PDF-эталон/агрегатор. `origin_url` обязателен: файл без URL происхождения в корпус не принимается.

## Шаг 2. Конвертировать

```bash
make convert DOC=sp-63-13330-2018
# или пакетно: make convert JOBS=8
```

На выходе:

```
md/sp-63-13330-2018.md              канонический текст
md/sp-63-13330-2018.qa.json         отчёт для машин
md/sp-63-13330-2018.qa.md           чек-лист для человека  ← начать отсюда
md/sp-63-13330-2018.tables.jsonl    нормализованные таблицы
md/sp-63-13330-2018.assets.json     манифест картинок
```

## Шаг 3. Разобрать QA-отчёт

```bash
cat md/sp-63-13330-2018.qa.md
```

| тип в чек-листе | что сделать |
|---|---|
| `formula` | сравнить LaTeX с оригиналом; выверенный вариант → `overrides/formulas/<doc_id>-eqNNN.yaml` |
| `table` | открыть HTML-таблицу и оригинал; проверить шапку, слияния, единицы; при расхождении — исправить в overrides и завести issue на конвертер |
| `xref` | неразрешённая перекрёстная ссылка: проверить, что кэш Word верный; при необходимости заменить вручную |
| `ole` | внедрённый объект (Visio/MathType): экспортировать в SVG/PNG, положить в ассеты |
| `image_format` | EMF/WMF → SVG: `soffice --convert-to svg` |
| `heading` | «стиль заголовок, но текст как пункт» — проверить уровень и номер |
| `field` | непокрытое поле Word — обычно безопасно игнорировать, но записать в issue |

Дополнительно прогони линт:

```bash
make lint            # ошибки: непарные $$, битые якоря, пропуски нумерации, отсутствующие картинки
```

## Шаг 4. Уточнить метаданные

Создай `overrides/sp-63-13330-2018.yaml` (схема — `schemas/overrides.schema.json`).
Поля — **плоские**, сливаются с распознанными автоматически (ручное побеждает);
`origin_url`/`origin_date`/`publisher`/`text_layer` попадают в блок `source:`:

```yaml
title: "Бетонные и железобетонные конструкции. Основные положения"
title_short: "Бетонные и железобетонные конструкции"
status: active
status_checked: "2026-10-16"
issuing_body: Минстрой России
issued: "2018-05-24"
in_force_since: "2018-08-01"
amendments: ["1", "2", "3"]
supersedes: [snip-52-01-2003]
topics: [железобетон, бетон, армирование, конструирование, расчёт]
ics: ["91.080.40"]
origin_url: "https://…"
origin_date: "2026-10-16"
```

Пересобери документ, чтобы overrides применились (кэш считается по флагам, не
по содержимому override-файлов — обязателен `--force` / `make convert DOC=…`,
который его передаёт):

```bash
make convert DOC=sp-63-13330-2018 && make lint
```

## Шаг 5. Верификация (если вычитываешь полностью)

Проверь по оригиналу:

- [ ] все разделы и подразделы на месте, номера совпадают;
- [ ] нумерация пунктов непрерывна (линт это проверит);
- [ ] все таблицы: шапки, единицы, слияния, сноски, примечания;
- [ ] все формулы и их «где»-блоки;
- [ ] числовые требования выборочно (минимум 20 случайных значений) — **обязательно**, это то, чем пользуются;
- [ ] подписи и `alt` у рисунков содержательны;
- [ ] приложения и их тип (обязательное / рекомендуемое / справочное).

Затем в overrides:

```yaml
conversion:
  verified: true
  verified_by: "Фамилия И.О."
  verified_at: "2026-10-16"
```

## Шаг 6. Pull request

```bash
git checkout -b doc/sp-63-13330-2018
git add md/sp-63-13330-2018.* overrides/sp-63-13330-2018.yaml sources/inventory.csv
make chunk catalog
git commit -m "doc(sp-63-13330-2018): добавлен, verified — таблицы 6.1–6.12, 4 формулы"
git push -u origin doc/sp-63-13330-2018
```

В описании PR — сводка из `md/sp-63-13330-2018.qa.json`: confidence, число таблиц/формул, закрытые пункты review, что осталось непроверенным. CI подставит её автоматически.

## Массовая загрузка

```bash
rsync -av /mnt/norms/batch-007/ inbox/
make convert JOBS=8 && make lint && make report
git checkout -b import/batch-007
git add md/ catalog/ sources/inventory.csv
git commit -m "import(batch-007): 118 документов, 4 в очередь review"
```

Правила: 50–300 документов на пакет; документы с `confidence < 0.9` не блокируют пакет, но попадают в раздел «Требует внимания» в `catalog/INDEX.md`; документы с ошибками линта — в отдельную ветку на доработку.
