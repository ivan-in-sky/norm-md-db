# AGENTS.md

Этот репозиторий — корпус нормативных документов строительства в каноническом Markdown. Правила ниже обязательны для любого агента (и для людей).

> Репозиторий публикуется из рабочего Obsidian-vault (`база/`); соответствие
> папок — `docs/03-storage.md` §6.1. Полный цикл ведения базы (разведка →
> скачивание → конвертация → сверка → индекс) — **`docs/10-local-agent.md`**;
> сводка для агента — `normconv/AGENTS.md` (в рабочем проекте).

## Жёсткие правила

1. **Не редактируй файлы в `md/` вручную.** Они генерируются конвейером `normconv` из оригиналов. Правки метаданных — в `overrides/<doc_id>.yaml`, словари символов — в `overrides/symbols/`, выверенные формулы — в `overrides/formulas/<doc_id>-eqNNN.yaml`. CI проверяет, что `md/` соответствует повторной конвертации, и ручные правки будут потеряны.
2. **Не редактируй `catalog/`, `index/`, `site/`.** Это производные артефакты: `make catalog`, `make chunk`, `make clauses`.
3. **Не удаляй и не меняй идентификаторы блоков** в конце абзацев: `^c8-1-6` (пункт), `^t3` (таблица), `^e012` (формула), `^f7` (рисунок). Это ссылки Obsidian и стабильные ключи индекса. Правила формата — `docs/01-architecture.md` §4.
4. **Изменил конвертер →** прогони `make lint` и `make check` (регрессии по `evals/golden/`). Без зелёных golden-тестов PR не мержится.
5. **Один PR = один документ или одно изменение инструмента.** Не смешивай массовый импорт с правками конвертера.
6. **Никогда не цитируй документ со статусом `superseded` как действующий.** Документ со статусом `unknown` цитируй с оговоркой «статус не сверен с реестром».
7. **В тексте документов не должно быть упоминаний справочных систем** (КонсультантПлюс/Техэксперт/Кодекс/cntd/Гарант): провенанс — только `vendor:`/`publisher:` во фронтмэттере и `sources/inventory.csv`. Проверка в CI и grep-ом (§«Как искать»).

## Команды

```bash
make convert JOBS=8     # sources/ → md/  (нормализация, конвертация, QA)
make lint               # CI-гейт: ненулевой код возврата при ошибках
make chunk              # md/ → index/chunks.jsonl (+ atoms, stats)
make catalog            # md/ → catalog/{jsonl,csv,yaml,INDEX.md}
make clauses            # md/ → catalog/CLAUSES.{md,jsonl} (пункт → block id → строка → ссылки)
make report             # md/_reports/dashboard.md — очередь ручной доработки
make eval               # фаза 2: evals/ — метрики качества RAG (нужен evals/run_eval.py)
make check              # фаза 2: lint + golden + eval (полная проверка)
```

## Формат данных

- Спецификация: `docs/01-architecture.md`; схемы: `schemas/*.json`.
- Пункт документа: `**8.1.6** текст… ^c8-1-6` (номер — видимый текст, идентификатор — block ID Obsidian в конце абзаца).
- Таблица: HTML `<table>` с `rowspan`/`colspan` + нормализованная сетка в `md/<doc_id>.tables.jsonl`.
- Формула: `$$ … $$` LaTeX; при низкой уверенности рядом комментарий `<!-- formula <id> | confidence 0.87 | REVIEW -->`.
- Рисунок: `<img … alt="содержательное описание">` + подпись `**Рисунок N — …**`.
- Метаданные документа: YAML-фронтмэттер (`doc_id`, `designation`, `status`, `amendments`, `conversion.confidence`, `topics`, `references`, …).

## Как искать в корпусе

1. Точное обозначение или пункт → `grep -rn "\^c8-1-6" md/` / `grep -n "\*\*8.1.6\*\*" md/…`; готовые ссылки (block id → строка → GitHub/Obsidian) — в `catalog/CLAUSES.md` / `CLAUSES.jsonl`.
2. Содержательный поиск → `index/chunks.jsonl` (эмбеддинги на стороне агента); MCP `norms.search` — фаза 2.
3. Применимость → `catalog/catalog.jsonl`: `status`, `kind`, `year`, `topics`, `amendments`, `excluded_clauses`.
4. Значения из таблиц → `md/<doc_id>.tables.jsonl` (поле `grid`), а не разбор HTML.
5. Чистота от СПС → `grep -rinE 'консультант|техэксперт|cntd|login\.consultant|ИС (\"|«)?Кодекс|СПС .{0,2}(Кодекс|Консультант|Техэксперт)|АО (\"|«)?(Кодекс|Техэксперт)|ярлык.{0,3}(\"|«)?Примечания|Примечание изготовителя|Документ предоставлен|Внимание! (Документ включен|О порядке применения)' md/ --include='*.md'` — допустимы только строки фронтмэттера `vendor:`/`publisher:`; голые «кодекс»/«гарант» в шаблон не входят («Градостроительный кодекс РФ» — закон, а не СПС). Файлы `.qa.md` фиксируют факт экспорта в счётчиках — штатно.

## Как цитировать в ответе

```
СП 63.13330.2018 «Бетонные и железобетонные конструкции. Основные положения»,
п. 8.1.6, с. 112 (действует, с изм. № 1–3)
```

Обязательные элементы: обозначение с годом, номер пункта, статус. Если `verified: false` или `confidence < 0.95` — добавь оговорку «по непроверенной автоматической конвертации, сверьте с официальным источником». Если ответа в корпусе нет — скажи это прямо, не выдумывай номера пунктов.

Подробные правила — в `skills/norms-citation/SKILL.md`.
