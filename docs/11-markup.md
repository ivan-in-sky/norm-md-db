# 11 · Разметка нормативных документов (канонический формат)

Единый источник правды для **тела** заметок в `база/документы/`. Фронтмэттер —
`01-architecture.md` §3, механика конвертации — `02-conversion.md`, формулы-картинки
— `08-wmf-formulas.md`. Рабочий скилл с алгоритмом доработки:
`.agents/skills/normconv-markup/SKILL.md`.

Документ описывает **целевой формат**: все новые документы создаются в нём,
старые приводятся к нему при доработке (элемент за элементом, §12).

---

## 1. Принципы

1. **Валидный Markdown**, одинаково рендерится в Obsidian и на GitHub, без плагинов.
2. **Ноль HTML-комментариев** в теле (`<!-- … -->` не несёт семантики и не
   допускается вообще; границы — только заголовками и block ID).
3. **У каждого элемента — block ID**: пункт `^c…`, таблица `^t…`, формула `^e…`,
   рисунок `^f…`, запись библиографии `^biblio-…`. ID = стабильный ключ для
   ссылок, чанков и указателя CLAUSES.
4. **Все формулы и буквенные обозначения — LaTeX** (`$…$` / `$$…$$`). Исключение —
   ячейки HTML-таблиц, где MathJax не работает: там `<i>`, `<sub>`, `<sup>` +
   юникод (φ, γ, σ).
5. **Никаких лишних пустых строк** (между блоками — ровно одна) и **лишнего
   форматирования** (жирные номера пунктов, жирные подписи таблиц/рисунков — нет).
6. **Определённость**: один и тот же вход даёт один и тот же вывод; ID стабильны
   между пересборками.

## 2. Скелет документа

```markdown
# СП 22.13330.2016 — Основания зданий и сооружений

> *(в ред. Изменения N 3, утв. Приказом Минстроя России от 22.11.2019 N 722/пр)*

## Предисловие

Текст…

## 1 Область применения

### 1.1 Общие положения

6.7.12 Расчетное сопротивление $R$ намывных грунтов определяется… ^c6-7-12

## Использованные нормативные документы

[1] СНиП 2.02.01-83*. Основания зданий и сооружений.
[2] ГОСТ 27751-2014. Здания и сооружения… ^biblio-2
```

### 2.1 Уровни заголовков

| уровень | что | пример |
|---|---|---|
| H1 | **заголовок документа** — один на файл | `# СП 22.13330.2016 — Основания зданий и сооружений` |
| H2 | разделы: Предисловие, Введение, 1…N, «Использованные нормативные документы», приложения | `## 8 Конструирование` |
| H3 | подразделы x.y | `### 8.1 Общие требования` |
| H4 | подподразделы x.y.z (редко) | `#### 8.1.1 …` |

- Пункты (x.y.z, x.y.z.w) **не являются заголовками** — это абзацы с block ID (§3).
- Приложение — **одним предложением**, название в заголовке:
  `## Приложение М — Основные буквенные обозначения`; пометка о редакции —
  blockquote сразу после заголовка:

  ```markdown
  ## Приложение М — Основные буквенные обозначения

  > *(в ред. Изменения N 3, утв. Приказом Минстроя России от 22.11.2019 N 722/пр)*
  ```

- Перед заголовком и после — одна пустая строка; других пустых строк нет.
- В заголовках без жирного/курсива, без block ID (якорь даёт сам заголовок).

## 3. Пункты

```markdown
6.7.12 Расчетное сопротивление $R$ намывных грунтов определяется в соответствии
с требованиями [5.6](СП%2022.13330.2016.md#5.6%20Расчет%20оснований%20по%20деформациям). ^c6-7-12
```

- **номер пункта — обычный текст, не жирный** (артефакт `**N**` убирается);
- `^c6-7-12` — в конце **первого** абзаца; многоабзацный пункт продолжается до
  следующего маркера;
- пункт не попадает в outline — это осознанно (иначе 1200 записей).

Перечисления: литерные маркеры как в оригинале (`а)`, `б)`, `1)`, `2)`), строки
**подряд, без пустых строк** — один абзац с мягкими переносами:

```markdown
6.7.13 Коэффициенты принимают: ^c6-7-13

а) для элементов при пролёте до 6 м — 1/200 пролёта;
б) для элементов при пролёте 6 м и более — 30 мм.
```

## 4. Формулы

Номерная дисплейная формула:

```markdown
$$E=\frac{A\,t\,K}{t+B/K_1}\tag{6.25}$$

^e047
```

- `\tag{…}` — номер **как в оригинале** (раздел.номер); без номера — без `\tag`;
- `^eNNN` — отдельная строка после формулы, сквозной порядковый номер (3 знака);
- стиль LaTeX: компактный, без пробелов вокруг `=`, подстрочные индексы `_1`;
  кириллица/греческие — юникодом (`ψ`, `φ`), не макросами;
- внутри `$$…$$` **без пустых строк**.

Блок «где» — одно обозначение на строку, без пустых строк:

```markdown
где $K_1$, $K_2$ — коэффициенты, то же, что и в формуле (6.25);
$A_1$, $B_1$ — безразмерные параметры, вычисляемые по формулам:
```

(строки подряд — один абзац с мягкими переносами; дисплейные формулы внутри
«где»-блока — отдельными `$$…$$` блоками)

**Все буквенные обозначения в тексте — inline-LaTeX**: `$R$`, `$\varphi_{II}$`,
`$c_{II}$`, `$t_1$`. `<sub>`/`<sup>` в тексте не допускаются. Группы предельных
состояний — римские: I, II (не 1, 11).

Нераспознанная формула — fenced-блок + картинка (никогда не выдумывать LaTeX):

````markdown
```formula sp-22-13330-2016-eq047
E=AK/(t+B/K')
```
````

## 5. Таблицы

```markdown
Таблица 4.1 — Расчетные значения коэффициентов

^t012

<table>
<tr><th>Грунты</th><th>Коэффициент <i>M</i><sub><i>q</sub></th></tr>
<tr><td>Пески</td><td>2,88</td></tr>
</table>
```

- **подпись — один абзац, без жирного, без переносов**: `Таблица N — Название`;
  таблицы приложений — `Таблица А.8`, `Таблица Л.6` (буква приложения + номер);
- `^tNNN` — отдельная строка между подписью и `<table>`;
- `<table>` — единственный HTML, потому что GFM не умеет `rowspan`/`colspan`;
  каждая `<tr>` — на одной строке;
- **внутри ячеек LaTeX не рендерится** (ни Obsidian, ни GitHub не прогоняют
  MathJax по raw-HTML) → символы пишутся как `<i>`, `<sub>`, `<sup>` + юникод:
  `<td><i>M</i><sub><i>q</sub></td>`, `<td>φ, град</td>`;
- сетка слияний — в sidecar `<doc_id>.tables.jsonl` (RAG и проверки);
- **подписи нет в источнике** → агент пишет её по контексту (пункт, который
  ссылается на таблицу) и фиксирует в QA. Служебного комментария «нет подписи»
  не остаётся.

## 6. Рисунки

```markdown
<img src="sp-22-13330-2016.assets/sp-22-13330-2016-607.png"
     alt="Алгоритм моделирования каркаса здания: сбор данных → определение жёсткостных характеристик → расчеты → проверка требований (цикл корректировки)" width="519" height="837" />

Рисунок Н.1 — Моделирование каркаса здания

^f067
```

- `alt` **обязателен и содержателен**: что изображено, ключевые обозначения
  (заполняется vision-моделью; пустой `alt=""` — дефект);
- подпись — один абзац: `Рисунок N — Название` + `^fNNN`;
- **пометка о редакции** — blockquote после подписи:

  ```markdown
  > *(рисунок 9.1 в ред. Изменения N 4, утв. Приказом Минстроя России от 27.12.2021 N 1022/пр)*
  ```

- **flowchart / деревья решений → mermaid** (рендерится и в Obsidian, и на GitHub):

  ````markdown
  ```mermaid
  flowchart TD
      A[Подготовительный этап (сбор данных)] --> B[Определение жёсткостных характеристик]
      B --> C{Требования удовлетворяются?}
      C -- Нет --> D[Корректировка конструктивных решений]
      D --> B
      C -- Да --> E[Окончательная разработка]
  ```
  ````

- схемы с размерами и графики с кривыми — PNG с подробным `alt` (данные не
  извлекаются; оцифровка — отдельная задача);
- `<!-- figure-caption-deferred -->` и прочие комментарии — запрещены.

## 7. Примечания, сноски, пометки редакций

```markdown
> **Примечание** — Для элементов с пролётом более 7,5 м прогиб уточняется расчётом.

> **Примечание 1** — …

> **Примечание 2** — …
```

- несколько примечаний — отдельные blockquote, нумерация как в оригинале;
- сноска: `[^fn3]` + определение внизу;
- нейтральная пометка введённого пункта — курсивом inline в конце пункта:
  `*(абзац введён Изменением N 1, утв. …)*`.

## 8. Перекрёстные ссылки

| цель | формат |
|---|---|
| пункт того же документа | `[6.7.8](СП%2022.13330.2016.md#^c6-7-8)` |
| раздел того же документа | `[5.6](СП%2022.13330.2016.md#5.6%20Расчет%20оснований%20по%20деформациям)` |
| таблица / рисунок / формула | `[Таблица 4.1](СП%2022.13330.2016.md#^t012)` |
| запись библиографии | `[2](СП%2022.13330.2016.md#^biblio-2)` |
| другой нормативный документ | `[[ГОСТ 27751]]` (беспроигрышный алиас) |

- `(см. 6.9)`, `(рисунок 6.14)`, `(формула 6.25)`, `(таблица А.8)` — **всегда
  ссылкой**, не голым текстом;
- пробелы в пути можно писать как есть или кодировать `%20` — оба варианта
  работают в Obsidian и на GitHub;
- на GitHub `#^…`-якоря вырождаются в текст (якорей в произвольных местах нет) —
  осознанно; точные строки даёт `каталог/CLAUSES.md`, «красивые» якоря —
  веб-зеркало (`01-architecture.md`, «Три слоя ссылок на пункт»).

## 9. Библиография

```markdown
## Использованные нормативные документы

[1] СНиП 2.02.01-83*. Основания зданий и сооружений.
[2] ГОСТ 27751-2014. Здания и сооружения. Методы комплексной оценки… ^biblio-2
```

- заголовок раздела — H2 (имя как в оригинале: «Использованные нормативные
  документы» / «Список литературы»);
- каждая запись — `^biblio-N`;
- маркеры `<!-- bibliography -->` **убраны**: граница для чанкера — сам заголовок.

## 10. Таблица block ID

| объект | префикс | пример | образование |
|---|---|---|---|
| пункт | `c` | `^c6-7-12` | номер, `.` → `-` |
| пункт приложения | `c` + транслит | `^ca-3`, `^cv-2-1` | «А.3» → `a-3` |
| таблица | `t` | `^t012` | сквозной порядковый (3 знака) |
| формула | `e` | `^e047` | сквозной порядковый (3 знака) |
| рисунок | `f` | `^f067` | сквозной порядковый (3 знака) |
| библиография | `biblio` | `^biblio-2` | номер записи |

Правила: только `[A-Za-z0-9-]`, уникальность в файле (проверяет линт),
детерминизм, стабильность. Занятый ID → суффикс `-2`, `-3` + QA-предупреждение.

## 11. Чего в теле быть не должно

| не кладём | почему |
|---|---|
| HTML-комментарии (`<!-- … -->`) | не Markdown, шум в Source mode и диффах; границы — заголовки + block ID |
| лишние пустые строки (≥2 подряд) | ломают «мягкие» абзацы перечислений и «где»-блоки |
| жирные номера пунктов (`**6.7.12**`) | номер — обычный текст; жирный = артефакт конвертера |
| жирные/разорванные подписи таблиц и рисунков | подпись — один абзац, обычный текст |
| `<sub>`/`<sup>` вне HTML-таблиц | в тексте — LaTeX |
| `alt=""` у рисунков | рисунок не находим семантическим поиском |
| переносы строк внутри подписей | подпись — один абзац |
| Word-артефакты: `<*>`, `<1>`, `AUTHOR`, `DOCPROPERTY` | смысл не несут |
| строки справочных систем («Документ предоставлен…») | факт экспорта — во фронтмэттере (`vendor`) и QA |
| колонтитулы, номера страниц, TOC Word | производное; страницы — в `pages.json` |

## 12. Алгоритм доработки (агент, элемент за элементом)

Доработка ведётся **по элементам**, а не «прогоном по файлу»: документ
разбивается на элементы, каждый проверяется по чек-листу и сверяется с
доверенным источником.

**Источники (приоритет):** официальный PDF (рендер страниц) > текстовый слой
PDF > экспорт СПС. При расхождении — выигрывает официальный PDF; расхождение
фиксируется в QA.

1. **Парсинг.** Разбить документ на элементы по block ID и структуре:
   заголовки, пункты, перечисления, таблицы, формулы (+ «где»-блоки), рисунки,
   примечания, библиография.
2. **Проверка каждого элемента** по чек-листу (§13).
3. **Сверка с источником**: таблицы — сетка (rowspan/colspan) и данные; формулы —
   символы, индексы, номер `\tag`; рисунки — подпись и содержание (vision);
   пункты — текст и нумерация.
4. **Правка in place** + синхронизация sidecar'ов (`<doc_id>.tables.jsonl`,
   фронтмэттер `stats`).
5. **Гейт**: `PYTHONPATH=tools python -m normconv.cli lint <файл>` → `error: 0`.
6. **Фиксация** в `<doc_id>.qa.md` и журнале обкатки.

## 13. Чек-листы по элементам

| элемент | проверки |
|---|---|
| заголовок | уровень по §2.1; приложение — одним предложением; пометка редакции — blockquote |
| пункт | номер не жирный; `^c…` в конце первого абзаца; перечисления подряд без пустых; ссылки — `[…](…#^c…)` |
| формула | LaTeX; `\tag{}` по оригиналу; `^eNNN`; «где»-блок полный, одно обозначение на строку |
| таблица | подпись один абзац; `^tNNN`; сетка валидна (rowspan/colspan); символы в ячейках — `<i>/<sub>`+юникод |
| рисунок | `alt` содержателен; подпись + `^fNNN`; пометка редакции; flowchart → mermaid |
| примечание | blockquote; нумерация как в оригинале |
| библиография | H2-заголовок; `^biblio-N` на каждой записи; ссылки `[N](…#^biblio-N)` в тексте |
| весь файл | ноль `<!-- -->`; ноль двойных пустых строк; ноль `<sub>` вне таблиц; lint `error: 0` |

## 14. Влияние на конвейер (что меняется в коде)

- **конвертер**: номера пунктов без `**`; генерация `^eNNN`/`^fNNN`; `\tag{…}`
  в формулах; подписи таблиц/рисунков — один абзац; HTML-комментарии не
  пишутся; заголовок документа — H1, разделы — H2;
- **линт**: новые проверки — нет комментариев, нет жирных номеров, `alt` не
  пуст, у каждой таблицы/формулы/рисунка есть ID, нет ≥2 пустых строк, нет
  `<sub>` вне `<table>`;
- **чанкер**: граница пункта — `^c…` (не `**N**`); библиография — по H2-заголовку;
- **существующие документы** приводятся к формату доработкой (§12), не
  пересборкой.
