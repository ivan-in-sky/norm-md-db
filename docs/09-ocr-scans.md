# 09 · Скан-документы: OCR-конвейер

> **Финальная редакция: 2026-10-23. Статус: путь A (PDF с текстовым слоем)
> реализован** — `pdf2md.py`: детектор повторяющихся/вендорных строк (включая
> скрытый колонтитул СПС с markdown-обвязкой и разрывами тире), склейка
> абзацев через страницы, разряженные номера, `pages.json`, словари символов
> `--glyphs`, мета-overrides; обкатан на трёх документах базы (ГОСТ 31937-2024,
> ГОСТ 27751-2014 + эталонные извлечения ФЦС/МЕГАНОРМ). **Классы B/C
> (чистые сканы) — исполнительная спецификация фазы 2** для локального агента;
> критерий запуска — `07-roadmap.md` §3, п. 2. Здесь — что делать, когда
> текстового слоя нет или ему нельзя верить.

## 1. Классы сканов, которые реально встречаются

Проверено на живых файлах базы:

| класс | пример из базы | признаки | стратегия |
|---|---|---|---|
| **A. Официальная публикация с OCR-слоем** | PDF ФАУ «ФЦС» (`api.faufcc.ru`): СП 56.13330.2021, СП 22.13330.2016 | скан ABBYY + текстовый слой; слой есть, но **потеряны подстрочные индексы** (`Nγ`→`N`), разметка заголовков отсутствует | слой — для структуры и поиска; формулы — только vision (§5); сам слой как источник формул **запрещён** |
| **B. Чистый скан без слоя** | копия зарегистрированного приказа с `e-spk.ru` (19.7 МБ, слоя нет) | изображение на страницу, `get_text()` пуст | полный OCR-конвейер (§3–5) |
| **C. «Книжные» сканы 80–90-х** | старые СНиП/ГОСТ на meganorm.ru, files.stroyinf.ru | низкое dpi, развороты на две страницы, штампы, машинописный шрифт, `П Р И М Е Ч А Н И Е` вразрядку | полный OCR + усиленная предобработка (§3) + обязательная сверка чисел |

Класс A — не «OCR-задача», а задача **восстановления структуры** из плоского
текста: она уже решается `pdf2md` + эвристиками заголовков. Классы B и C —
собственно OCR.

## 2. Зондирование: определить класс до всякой работы

Для каждого PDF (готовый рецепт скрипта — `10-local-agent.md` §6.1, ~1 с на
документ):

```
текст/страницу   = len(page.get_text().strip())
покрытие_слоем   = площадь текстовых блоков / площадь страницы
изображение      = page.get_images() → dpi = pixel_w / (rect_w/72)
кодек            = CCITT/JBIG2 → почти наверняка 1-битный скан
слой_цифровой    = текст извлекается с нормальными пробелами И dpi изображений > 300
                   И нет картинки на всю страницу → это НЕ скан (векторный PDF)
```

Решение:
- цифровой PDF → обычный `pdf2md` (не этот документ);
- класс A → `pdf2md` + символы по словарю `--glyphs`; формулы — только vision
  (§5, фаза 2); сам слой как источник формул **запрещён**;
- классы B/C → OCR-конвейер ниже (фаза 2);
- **A/B-сомнение** (слой есть, но мусорный: `%` кракозябр, склейки слов) →
  считать классом B: пере-OCR чище, чем чинить плохой слой.

Результат зондирования пишется в `источники/inventory.csv` (колонки
`text_layer`, `source_tier`, при OCR — scan_class в `notes`) — агент не должен
зондировать одно и то же дважды.

## 3. Предобработка (класс C, частично B)

Порядок операций (OpenCV/pymupdf, всё детерминированно):

1. **Кадрирование полей:** отрезать поля с номерами страниц, колонтитулами,
   библиотечными штампами.
2. **Удаление вендорских водяных знаков** — обязательное требование проекта
   (очистка от упоминаний справочных систем): надписи «Техэксперт»,
   «КонсультантПлюс», логотипы агрегаторов — кроп, если на полях; inpaint,
   если по тексту. Обложки издательств в базу не попадают вовсе (см.
   `06-licenses.md` — не воспроизводить оформление официальных изданий).
3. **Разрезка разворотов:** старые СНиП сканированы разворотом «две страницы на
   лист». Детектор: широкая страница (aspect > 1.5) + вертикальная долина
   пустого пространства в середине → разрезать на две.
4. **Дескью** (OSD Tesseract / оценка по профилям строк) — перекос > 0.5°
   заметно роняет качество OCR.
5. **Бинаризация/денойз** (Sauvola, median) — только для класса C; современные
   сканы (B) обычно не требуют и портятся от агрессивной обработки.

Каждый шаг — с флагом в QA: что применено, к каким страницам. Предобработка
необратима, поэтому **исходный скан всегда остаётся в `источники/` untouched**.

## 4. Выбор OCR-движка

| движок | плюсы | минусы | роль в проекте |
|---|---|---|---|
| **Tesseract 5** (`rus`) | бесплатный, hOCR/TSV с координатами и confidence по словам | посредственен на таблицах и формулах, старая типографика | базовый движок, координаты + уверенность |
| **ABBYY FineReader / Recognition Server** | лучший по русским нормативам: таблицы, сноски, двухколоночник | коммерческий | если доступен — основной для класса C |
| **Surya / PaddleOCR** | современные ML-модели, хороший layout | тяжелее в установке | альтернатива/второй движок |
| **docling / marker** | готовые пайплайны «PDF → Markdown» с таблицами и заголовками | качество на сканах 90-х непредсказуемо | быстрый старт: прогнать, посмотреть, решить |

**Правило двух движков** для всего, что пойдёт в индекс как `verified-кандидат`:
критичный документ прогоняется двумя независимыми движками, тексты
диффятся; расхождения (особенно цифры!) — в очередь ревью. Расхождение двух
движков — лучший бесплатный детектор ненадёжных мест.

## 5. Восстановление структуры после OCR

OCR даёт плоский текст (в лучшем случае — с координатами слов). Канонический
Markdown собирается так:

1. **Заголовки разделов:** паттерны ГОСТ 1.5 — `N Заголовок`, `N.M Подзаголовок`;
   строки CAPS; увеличенный кегль (из координат/TSV). Эвристики те же, что в
   `docx2md` для «ручной нумерации» — переиспользовать.
2. **Пункты:** номер в начале строки (`4.1`, `Б.3`) + проверка **непрерывности
   нумерации** (уже реализована в `lint.py`): пропуск 4.7→4.9 = почти наверняка
   ошибка OCR или потерянная страница.
3. **Таблицы — самое уязвимое место сканов.** Порядок:
   детекция области таблицы (линии сетки / плотная табличная раскладка) →
   кроп → vision-модель → HTML → нормализованная сетка в `.tables.jsonl`
   (тот же формат, что из docx). Табличный OCR движками допускается только
   как фолбэк и всегда с флагом `table_ocr_unverified`.
4. **Формулы:** кроп области формулы → пайплайн `08-wmf-formulas.md` §5.1
   (vision + обратный рендер). Никогда не брать формулу из OCR-текста:
   индексы теряются всеми движками (это же сломало текстовый слой ABBYY у
   официального ФЦС-издания).
5. **Сноски/примечания:** паттерны `Примечание`, `*`, `¹`; нормализация
   вразрядки (`П р и м е ч а н и е` → `Примечание`) уже есть в конвейере.
6. **Нумерованные списки:** `а)`, `б)`, `1)`, `2)` — блок-ID перечислений `^i…`
   как в docx-пути.

Выход — тот же канонический `.md` + sidecars, что и из docx: дальше документ
идёт по общему маршруту (obsidian-очистка → lint → QA → индекс).

## 6. Уверенность и контроль качества

- Из TSV/hOCR берётся **confidence по словам** → агрегаты: на страницу, на
  пункт, на документ. Во фронтмэттер: `source.kind: ocr`, `ocr_confidence`,
  `ocr_engine`, `ocr_second_engine_diff: N%`.
- Порог: документ с `ocr_confidence < 0.85` не индексируется как доверенный —
  в чанках остаётся `confidence`, и RAG-слой обязан его учитывать (правило уже
  заложено в payload-фильтры `04-rag.md`).
- **Точечная сверка чисел обязательна независимо от confidence:** случайные 20
  числовых значений (таблицы, требования пунктов) сверяются с картинкой
  страницы (человеком или vision). Числа — то, ради чего базу открывают.
- Двойной OCR-прогон (§4) — для всех документов класса C.

## 7. Правовой аспект

- Текст официального документа (СП, ГОСТ, СНиП) не является объектом
  авторского права (пп. 1 п. 6 ст. 1259 ГК РФ) — OCR и хранение текста законны
  (подробно — `06-licenses.md`).
- **Но:** обложки, оформление и водяные знаки издательств/справочных систем в
  базу не копируются; скан-оригинал с чужим водяным знаком не публикуется —
  только очищенный текст.
- Провенанс каждого скана — в `источники/inventory.csv`: откуда, когда, sha256.

## 8. Порядок работы локального агента (псевдокод)

```
1. probe(pdf) → класс A | B | C | цифровой            (§2)
2. если A: pdf2md → формулы vision (doc 08) → готово
3. если B/C:
     препроцессинг: кадрирование → водяные знаки → развороты → дескью → (C) бинаризация   (§3)
     ocr1 = tesseract(pages)                          (TSV: текст + координаты + confidence)
     ocr2 = второй движок, если документ критичный    (§4)
     структура: заголовки → пункты → таблицы(vision) → формулы(vision)                    (§5)
     md = канонический markdown + sidecars
4. obsidian-очистка → lint (0 errors — жёсткий гейт)
5. QA: ocr_confidence, diff двух движков, spot-check 20 чисел                            (§6)
6. документы/<обозначение>.md; в inventory.csv — scan_class, engines, confidence
7. compare с официальной публикацией, если она есть (покрытие текста, страницы)
```

## 9. Чего не делать

| соблазн | почему нельзя |
|---|---|
| OCR-ить документ, у которого уже есть хороший цифровой слой | потеря качества и времени: цифровой текст всегда чище |
| Брать формулы/индексы из OCR-текстового слоя | индексы теряются всеми движками (кейс ABBYY у ФЦС это доказал на официальной публикации) |
| «Улучшать» текст по смыслу (очевидная опечатка → исправить молча) | правки — только через `правки/` с фиксацией; текст норматива неприкосновенен |
| Публиковать исходный скан с водяными знаками | вендор-очистка — требование проекта; см. также `06-licenses.md` |
| Доверять одному движку на классе C | правило двух движков — единственный бесплатный детектор числовых ошибок |
