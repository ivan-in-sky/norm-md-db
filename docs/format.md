# Формат канонического Markdown (контракт данных)

Спецификация файлов в `data/`. Это правила **перевода существующих документов в цифровое
представление**, не правила выпуска официального издания: формулировки, нумерация и
названия — как в источнике; Markdown-разметка, block ID и sidecar — наши правила цифровой адаптации.

## 1. Нормативные основания

| Документ | Что берём |
|---|---|
| **ГОСТ Р 1.19-2023** «Своды правил…» (профильный для СП) | построение/нумерация, пометы при переиздании (§7.4), нумерация таблиц/рисунков/формул внутри раздела |
| **ГОСТ 1.5-2001** (межгосударственные стандарты) | правила оформления, на которые ссылается ГОСТ Р 1.19-2023 |

Деление на разделы/пункты, подписи и состав элементов считываем из источника;
курсив меток, block ID, JSONL-сетки, чанки — наши правила. Старый документ сохраняет
собственную редакцию: новые правила оформления его текст не подменяют.

## 2. Именование

```
doc_id = <kind>-<number-slug>[-<year>]     # латиница; «.» и «/» → «-»
       sp | snip | gost | gost-r | rd | mds | vsn …
СП 63.13330.2018 → sp-63-13330-2018        ГОСТ Р 57345-2016 → gost-r-57345-2016
```

Два имени у каждого документа: `doc_id` — машинный ключ (фронтмэттер, каталог, чанки);
**имя папки/заметки** — обозначение кириллицей как есть (`data/сп/СП 22.13330.2016/СП 22.13330.2016.md`).

Состав папки документа:

```
СП 22.13330.2016/
├── СП 22.13330.2016.md        # канонический текст (frontmatter + тело)
└── assets/                    # рисунки, формулы-картинки; пути в md — относительные
```

Sidecar-файлы конвейера (`.qa.md`, `.tables.jsonl`, `.pages.json`, …) лежат рядом, но не публикуются.

## 3. Фронтмэттер (контракт данных)

Порядок ключей стабилен — его задают конвертеры. Обязательные поля
(отсутствие = ошибка линта): `doc_id`, `title`, `status`, `license`; остальные из списка ниже — предупреждение.

```yaml
---
# ---- идентификация ----
doc_id: sp-56-13330-2021          # стабильный машинный ключ, НЕ меняется
designation: СП 56.13330.2021     # как цитировать
kind: sp
number: 56.13330.2021
title: ПРОИЗВОДСТВЕННЫЕ ЗДАНИЯ
aliases:                          # механизм «ссылки не стареют» (§8)
  - СП 56.13330.2021              #   полное текущее
  - СП 56.13330                   #   беспроигрышное — на него ведут ссылки в текстах
  - СНиП 31-03-2001               #   заменённый документ — старая ссылка приведёт сюда
year: 2021
issued: 27 декабря 2021 г.
issuing_body: Минстрой России

# ---- правовой и административный статус ----
status: unknown                   # active | superseded | draft | rejected | unknown | licensed
supersedes: [snip-31-03-2001]     # doc_id заменённых документов
other_designations: [СНиП 31-03-2001]
superseded_by: ""
amendments: []                    # номера изменений, включённых в текст
excluded_clauses: []              # [{clause, range_to?, since, amendment}] — НЕ действующие требования

# ---- провенанс ----
source:
  kind: docx                      # docx | doc | pdf | ocr
  file: sp_56_13330_2021.docx
  sha256: a762d300…
  uri: "https://…"                # полный реестр — data/inventory.csv

# ---- качество конвертации ----
conversion:
  tool: normconv
  version: 0.1.0
  converted_at: "2026-10-23T05:03:51+00:00"
  confidence: 0.793               # 0..1; ≥0.95 — зелёный, <0.8 — обязательный триаж
  needs_review: true
  review_items: 19
  verified: false                 # true ставит ТОЛЬКО человек

# ---- блоки и статистика ----
blocks: {clauses: 256, ids: 294, tables: […], figures: […], formulas: 0}
stats: {words: 17746, headings: {"1": 9}, tables: 10, formulas: 0, xrefs: "41/44"}
license: официальный документ (ГК РФ ст.1259 п.6)   # лицензия к текстам нормативов неприменима
---
```

## 4. Скелет и заголовки

| уровень | что |
|---|---|
| H1 | **заголовок документа** — один на файл: `# СП 22.13330.2016 — Основания зданий и сооружений` |
| H2 | разделы: Предисловие, Введение, 1…N, «Использованные нормативные документы», приложения |
| H3 | подразделы x.y с фактическим заголовком в источнике |

- Пункты (x.y.z) **не являются заголовками** — это абзацы с block ID.
- Приложение — названием в H2: `## Приложение М — Основные буквенные обозначения`;
  пометка о редакции — blockquote сразу после заголовка.
- В заголовках без жирного/курсива и block ID; перед/после заголовка одна пустая строка.

## 5. Пункты

```markdown
6.7.12 Расчетное сопротивление $R$ намывных грунтов определяется… ^c6-7-12
```

- **номер пункта — обычный текст, не жирный**; `^c…` в конце первого абзаца;
  многоабзацный пункт продолжается до следующего маркера.
- Перечисления: литерные маркеры как в оригинале (`а)`, `б)`, `1)`), строки подряд —
  один абзац с мягкими переносами (не заменять на `-`/`1.`).

## 6. Формулы и обозначения

```markdown
$$E=\frac{A\,t\,K}{t+B/K_1}\tag{6.25}$$

^e047
```

- `\tag{…}` — номер **как в оригинале**; без номера — без `\tag`; `^eNNN` — отдельная строка.
- Все буквенные обозначения в тексте — inline-LaTeX: `$R$`, `$\varphi_{II}$`; `<sub>`/`<sup>` в тексте не допускаются.
- Блок «где» — одно обозначение на строку, подряд без пустых строк.
- Десятичная запятая в LaTeX: `2{,}88`.
- **Нераспознанная формула** — изображение с честным alt (`assets/eqNNN.png`, «распознавание не подтверждено») + `^e…`;
  LaTeX никогда не выдумывается.

## 7. Таблицы

```markdown
Таблица 4.1 — Расчетные значения коэффициентов

^t012

<table>
<tr><th>Грунты</th><th>Коэффициент <i>M</i><sub><i>q</sub></th></tr>
<tr><td>Пески</td><td>2,88</td></tr>
</table>
```

- Подпись — один абзац, без жирного: `Таблица N — Название`; **нет в источнике → только номер**
  (название не выдумывается; поисковое имя — в sidecar с пометкой inferred).
- Простая сетка без слияний может быть GFM-таблицей; **слияния (`rowspan/colspan`) — HTML `<table>`**,
  нормализованная сетка — в sidecar `.tables.jsonl`.
- Внутри ячеек LaTeX не рендерится → `<i>`, `<sub>`, `<sup>` + юникод: `<td><i>M</i><sub><i>q</sub></td>`.

## 8. Рисунки

```markdown
<img src="assets/sp-22-13330-2016-607.png" alt="Алгоритм моделирования каркаса: …" width="519" height="837" />

Рисунок Н.1 — Моделирование каркаса здания

^f067
```

- `alt` обязателен и содержательный (пустой `alt=""` — дефект); подпись один абзац + `^fNNN`.
- Алгоритмические схемы могут дополнительно даваться mermaid; исходное изображение сохраняется.

## 9. Примечания, пометки редакций

```markdown
> **Примечание** — Для элементов с пролётом более 7,5 м прогиб уточняется расчётом.
```

- Несколько примечаний — отдельные blockquote, нумерация как в оригинале; сноска `[^fn3]`.
- Нейтральная пометка введённого пункта — курсивом inline: `*(абзац введён Изменением N 1, утв. …)*`.
- Пометы при переиздании (ГОСТ Р 1.19-2023 §7.4): после изменённого/нового элемента —
  **полужирная** `(Измененная редакция, Изм. № N)`; для нескольких последовательных пунктов —
  общая помета после последнего с охватом (`3.9, 3.10 **(Введены дополнительно, Изм. № 2).**`);
  исключённые элементы — номер + `> [!warning] … исключены …`, текст не воспроизводится.

## 10. Перекрёстные ссылки и библиография

| цель | формат |
|---|---|
| пункт того же документа | `[6.7.8](СП%2022.13330.2016.md#^c6-7-8)` |
| таблица / рисунок / формула | `[Таблица 4.1](…md#^t012)` |
| запись библиографии | `[2](…md#^biblio-2)` |
| другой нормативный документ | `[[ГОСТ 27751]]` (беспроигрышный алиас) |

`(см. 6.9)`, `(рисунок 6.14)`, `(формула 6.25)` — всегда ссылкой, не голым текстом.
Библиография: H2-заголовок как в оригинале; каждая запись `^biblio-N`.

## 11. Block ID

| объект | префикс | пример | образование |
|---|---|---|---|
| пункт | `c` | `^c6-7-12` | номер, `.` → `-`; приложение: транслит (`^ca-3`) |
| таблица / формула / рисунок | `t` / `e` / `f` | `^t012`, `^e047`, `^f067` | сквозной порядковый (3 знака) |
| библиография | `biblio` | `^biblio-2` | номер записи |

Правила: только `[A-Za-z0-9-]`; уникальность в файле (проверяет линт); стабильность между пересборками.
ID — одновременно валидный текст, кликабельная ссылка (Obsidian) и машиночитаемый якорь.

## 12. Чего в теле быть не должно

HTML-комментарии `<!-- -->`; двойные пустые строки; жирные номера пунктов (`**6.7.12**`);
жирные подписи таблиц/рисунков; `<sub>`/`<sup>` вне HTML-таблиц; `alt=""`; Word-артефакты
(`<*>`, `AUTHOR`, `DOCPROPERTY`); строки справочных систем («Документ предоставлен…» — провенанс
во фронтмэттере `vendor:` и в QA); колонтитулы, номера страниц, TOC.

## 13. Ссылки между документами (алиасы)

Вики-ссылки **без года** ведут на действующую редакцию: `[[СП 22.13330]]` → резолвинг по
`aliases:` во фронтмэттере + `data/registry.yaml`. Алиасы включают старые обозначения
(`[[СНиП 2.02.01-83]]` приведёт на `СП 22.13330.2016`). **Красная ссылка** = документ ещё не в базе —
кандидат на скачивание, это нормально. Точная ссылка: `[[СП 22.13330.2016#^c8-1-6]]`.

## 14. RAG и цитирование

Границы чанков — структура (раздел → пункт → перечисление → таблица/формула/рисунок),
не произвольные токены; примечания не выглядят как требования (`kind`). Цитата нормы
обязательно содержит: обозначение, срез редакции, номер пункта и ссылку на источник.
Изменённый элемент — с номером изменения; `image_only`/`needs_review`-элементы не цитируются
как проверенные.
