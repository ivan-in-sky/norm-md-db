## 4. Трудозатраты (ориентиры, подтверждённые практикой)

| операция | факт/оценка |
|---|---|
| конвертация docx (автоматика) | секунды на документ |
| конвертация PDF 60–220 стр. (pdf2md) | 0,5–3 мин |
| эталон-сверка + страницы | минуты (автоматика) + 10–30 мин выборочного разбора расхождений |
| полный цикл на документ (агент, без vision/OCR) | **0,5–2 ч** включая инвентаризацию, сверки, отчёты (факт по четырём документам базы) |
| словарь символов документа (как ГОСТ 27751: 7 символов) | 1–2 ч с независимой сверкой по второй копии издания |
| WMF-формулы СП 22 (740 позиций: ~50 уникальных символов + 53 целых формулы) | оценка фазы 2: 1–2 дня тракта + часы vision с кэшем + верификация словаря человеком |
| ручная верификация документа до `verified` | 20–120 мин (чек-лист в `repo-template/CONTRIBUTING.md`) |
| OCR-верификация скана класса C | 2–4 ч выборочно (100% заголовков и таблиц, 10–20% абзацев, все числа) |

Вывод, подтверждённый практикой: автоматика бесплатна и быстра; бюджет проекта —
**верификация и словари формул**. Поэтому конвейер выдаёт точечный чек-лист
(«проверь эти 7 символов и 2 таблицы»), а не «документ сконвертирован, удачи».

## 5. Риски и как они снижаются

| риск | вероятность | последствия | снижение (действующее) |
|---|---|---|---|
| Формула/таблица сконвертирована «правдоподобно неправильно» | высокая без верификации | худший сценарий для нормативной базы | confidence + очередь `.qa.md`; нераспознанная формула индексируется без псевдо-LaTeX; `verified` только человеком; evals (фаза 2, п. 5) |
| Документ отменён, а база говорит «действует» | высокая | опасные рекомендации | `status` в каждом чанке + еженедельная сверка реестров (§13 ранбука); красная линия: отменённое не цитируется; до сверки — `unknown` с оговоркой |
| Экспорт СПС новее/старше официального издания | уже случилось (СП 22, ГОСТ 27751) | «потери» при сверке, путаница редакций | compare классифицирует «исключено изменением»; объяснённые расхождения — `правки/сверка-*.yaml`; `amendments`/`excluded_clauses` во фронтмэттере |
| Претензия правообладателя | низкая/средняя | удаление контента, репутация | только тексты (ст. 1259 п.6 ГК РФ), без сканов/обложек/оформления; провенанс в inventory; дисклеймер «не официальное издание»; takedown-процедура в NOTICE (фаза 2 — до публикации) |
| База «протухла»: никто не обновляет редакции | высокая через год | потеря доверия | регламент еженедельного прогона реестров; CHANGELOG; красные ссылки как индикатор живости |
| Ручные правки потерялись при переконвертации | высокая без дисциплины | повторная работа, демотивация | правки только через `правки/`; детерминизм + `--force`; diff пересборки показывает только `converted_at` |
| Ошибка в словаре глифов (системная) | средняя | портит все формулы с этим символом | верификация словаря человеком + материалы в `правки/материалы/`; независимая сверка по второй копии издания (кейс γ_n «=» по МЕГАНОРМ) |
| Один агент/человек знает всё | высокая | проект умирает | самодостаточный ранбук `docs/10`, сводка `AGENTS.md`, рецепты реальных документов, этот файл |

## 6. Если коротко: что делать следующим

1. Взять топ красных ссылок из `база/README.md` и прогнать первый документ
   по мастер-алгоритму `10-local-agent.md` §3 (рецепты — Приложение B).
2. На локальной машине: закрыть `status` у четырёх существующих заметок (§9.1
   ранбука) и восстановить `origin_url` ГОСТ 31937-2024.
3. Там же: запустить WMF-тракт по `08-wmf-formulas.md` для СП 22 (первый
   потребитель словаря глифов).
4. Держать инварианты: lint `error: 0` перед индексацией; производные
   пересобраны после каждой заметки; правки только через `правки/`.
5. Публикацию (фаза 2, п. 3) не начинать раньше ≥ 30–50 документов и
   ≥ 10 `verified`.
