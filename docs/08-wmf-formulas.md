# 08 · Формулы-картинки WMF: восстановление символов и формул

> **Финальная редакция: 2026-10-23. Статус: исполнительная спецификация фазы 2
> (vision-тракт) + реализованная инфраструктура.**
>
> Уже реализовано в конвейере и обкатано в бою: инвентаризация и QA-флаги
> картинок-формул, словарь символов `--glyphs` (детерминированная подстановка
> с провенансом по sha256, счётчиком применений и warning при нуле), override-
> механизм `правки/` (кейс ГОСТ 27751-2014: 7 из 7 символов, §10).
> Запускается на локальной машине (фаза 2): рендер WMF → PNG/SVG
> (LibreOffice/Inkscape), vision-транскрипция целых формул с обратным рендером
> и кэшем, применение `правки/формулы/<doc_id>-eq<N>.yaml`. Общая стратегия
> формул — в `02-conversion.md` §4; этот документ разбирает **худший случай**:
> экспорт справочных систем, где формулы набраны сотнями крошечных WMF-картинок.

## 1. Проблема в фактах

Замерено на реальном документе — СП 22.13330.2016, экспорт КонсультантПлюс (1.95 МБ `.docx`):

| факт | значение |
|---|---|
| всего ассетов | 611 |
| из них WMF | **580** (остальные 31 PNG — настоящие рисунки/схемы) |
| крошечные WMF (< 60×40 px) — отдельные символы | **405** |
| широкие WMF (≥ 150 px) — формула целиком одной картинкой | **53** |
| максимум символьных WMF подряд в одной строке | 6 |
| OMML-формул (нормальная математика Word) | **0** |
`alt` у всех картинок — `Консультант Плюс` (вычищается obsidian-слоем сразу).

Почему так: редакторы справочных систем при экспорте в `.docx` не умеют OMML и
раскладывают формулу на **отдельные картинки-символы** (переменная, индекс, знак),
расставляя их inline. Исходная структура формулы (дроби, индексы, скобки) при этом
теряется — остаются только порядок следования, размеры и смещения по вертикали.

Второй источник формул — официальные PDF ФАУ «ФЦС»: это сканы с текстовым слоем
ABBYY, который **теряет подстрочные индексы** (`Nγ` превращается в `N`, `R0` — в `R0`
без различения «ноль-индекс / о-буква»). Текстовый слой официальной публикации
для формул **не используется как источник** — только как слабая сверка состава
переменных (см. §5.1).

Последствие для качества: confidence СП 22 = 0.265, в очереди ручной доработки
860 позиций, из них 740 — картинки. Пока WMF не восстановлены, документ пригоден
для поиска по тексту, но **не** для ответов про расчётные формулы.

## 2. Цель и не-цель

**Цель:** каждая формула документа получает одно из трёх состояний:

1. LaTeX (`$…$` / `$$…$$`) с `confidence` и `method` (словарь / vision / manual);
2. картинка (SVG/PNG) с QA-флагом `formula_image` и координатами — «ещё не расшифрована»;
3. ручной override (`правки/формулы/<doc_id>-eq<N>.yaml`) — эталон.

**Не-цель:** 100 % автоматика. Формула — место, где агент выдаёт *правдоподобную*
ошибку (перепутал индекс, потерял множитель 0.5), и это худший сценарий для
нормативной базы. Поэтому: всё, что ниже порога уверенности, не попадает в
индекс как текст формулы и живёт в очереди ревью.

## 3. Шаг 0 — инвентаризация и дедупликация (без LLM)

Прежде чем что-либо распознавать:

1. **Дедупликация по sha256 байтов WMF.** Экспорт КонсультантПлюс переиспользует
   одни и те же файлы символов: 580 вхождений схлопываются в десятки уникальных
   картинок. Распознавать нужно уникальные, а не вхождения.
2. **Классификация по геометрии** (width/height из `<img>` или из заголовка WMF):
   - `symbol`: h ≤ 40 px — кандидат в словарный запас (§5.2);
   - `formula`: w ≥ 150 px — на vision целиком (§5.1);
   - `mixed/figure`: остальное — решать по контексту абзаца.
3. **Контекстная привязка:** для каждого `<img>` — абзац, позиция в абзаце,
   соседние текстовые run'ы, наличие номера формулы `(Б.1)`, `(5.3)` в конце
   строки. Номер формулы — якорь: блоковая WMF-формула почти всегда стоит
   отдельным абзацем непосредственно перед номером.
4. **Результат шага:** `формулы-инвентарь.jsonl` — по строке на уникальную
   картинку: sha256, класс, число вхождений, координаты вхождений.

Этот шаг детерминированный, дешёвый и сокращает объём дорогой работы на порядок.

## 4. WMF → растр/вектор (инфраструктура)

WMF — метафайл Windows, ни Pillow, ни браузеры его не читают. Варианты конвертации
(в порядке предпочтения):

| инструмент | команда | примечание |
|---|---|---|
| LibreOffice headless | `soffice --headless --convert-to svg *.wmf` | лучший по качеству; в песочнице его нет — на локальной машине ставится первым делом |
| Inkscape | `inkscape in.wmf --export-filename=out.svg` | надёжен для WMF/EMF |
| libwmf | `wmf2svg` / `wmf2gd` | лёгкий, без GUI-зависимостей |
| ImageMagick | `magick in.wmf out.png` | через делегаты; качество хуже |

Для vision рендерим PNG в **300–600 dpi** (крошечный символ 20×26 px при 600 dpi
даёт читаемую картинку ~170×220). Для сверок храним SVG.

## 5. Стратегии по классам

### 5.1 Целые формулы (53 шт. у СП 22) — vision-транскрипция

1. WMF → PNG 600 dpi.
2. **Два независимых прогона** локальной vision-модели (разный prompt/температура):
   «перепиши формулу в LaTeX, только математика, без пояснений».
3. Транскрипции совпали → `confidence = 0.9`, `method = vision`.
   Разошлись → третий прогон + очередь ручного ревью; в текст пока — картинка.
4. **Проверка обратным рендером:** LaTeX → (matplotlib mathtext или KaTeX) → SVG
   → грубое визуальное сравнение с исходным PNG (профиль «чернил» по строкам,
   размеры). Несовпадение силуэта ловит «правдоподобный, но другой» LaTeX.
5. **Слабая сверка с официальным PDF:** в текстовом слое ФЦС-публикации та же
   формула присутствует линеаризованной и без индексов (`N` вместо `Nγ`). Это не
   источник истины, но детектор галлюцинаций: если в vision-LaTeX появилась
   переменная, которой нет даже в линеаризованном тексте, — флаг на ревью.
6. Результат → `правки/формулы/<doc_id>-eq<N>.yaml` + кэш по
   `sha256(PNG) + версия модели`: повторные прогоны корпуса бесплатны.

### 5.2 Символьные цепочки (405 шт.) — глиф-словарь + детерминированная сборка

Ключевая идея: **уникальных символов мало, вхождений много.**

1. Прогнать vision (или разобрать вручную — их десятки) по **уникальным** WMF
   из класса `symbol` → словарь `sha256 → {latex, тип}`:
   `{"ab12…": {"latex": "R", "type": "var"}}`, `{"cd34…": {"latex": "_{0}", "type": "subscript"}}`, …
2. Словарь верифицируется человеком **один раз** и версионируется. Ошибка в
   словаре системна (портит все формулы с этим символом), поэтому словарь — самый
   охраняемый артефакт пайплайна.
3. **Сборка цепочки** (детерминированная, без LLM):
   - группа = подряд идущие inline-WMF одного абзаца + примыкающие текстовые run'ы
     (порядок = порядок в документе);
   - надстрочный индекс: символ уменьшен (h ≈ 60–70 % от номинала) и поднят
     относительно базовой линии (смещение из `wp:positionV` / `w:vertAlign` /
     разницы baseline соседних картинок) → `^{…}`;
   - подстрочный: уменьшен и опущен → `_{…}`;
   - крупные операторы (√, ∑, ∫) «поглощают» следующую группу до закрывающего
     признака (скобка / конец группы);
   - пробелы между токенами — по горизонтальным зазорам между картинками.
4. Честное ограничение: дробь, разложенная экспортом в линейную цепочку,
   останется `a/b`, а не `\frac{a}{b}`. Для поиска и чтения это приемлемо;
   в QA ставится флаг `linearized_fraction` — при желании человек доводит
   лучшие места через override.
5. `method = dict`, confidence = минимальная уверенность глифов цепочки.

### 5.3 Средний класс и рисунки

Картинки, которые не формулы (схемы, графики, чертежи узлов): конвертировать в
SVG/PNG, получить у vision подпись (`alt`), флаг `figure_needs_caption` в QA.
Никакой математики — не портить словарь.

## 6. Куда складываются результаты

**(а) Словарь символов — реализовано.** `правки/символы-<doc_id>.yaml`,
применяется флагом `--glyphs` при каждой (пере)конвертации — и в docx-пути
(`cli convert`), и в pdf-пути (`pdf2md`):

```yaml
- sha256: ae351aad…                     # провенанс: хэш изображения-источника
  find: "по нагрузке , коэффициенты"     # литерал канонического Markdown с «дырой»
  repl: "по нагрузке $\\gamma_f$, коэффициенты"
  note: "γ_f — коэффициент надежности по нагрузке (п. 2.2.13)"
```

Счётчик применений каждого правила пишется в QA (`glyph_substitution`);
ноль применений = warning. Материалы верификации (кропы изображений, контактные
листы, пары из независимых копий издания) — `правки/материалы/<doc_id>/`.

**(б) Формулы целиком — фаза 2 (формат фиксируется сейчас).**
`правки/формулы/<doc_id>-eq<N>.yaml`:

```yaml
id: sp-22-13330-2016-eq012
source_sha256: <WMF или собранного стрипа>
latex: "R = R_{0}[1 + k_{1}(b - b_{0})/b_{0}](d + d_{0})/(2d_{0})"
confidence: 0.92
method: dict | vision | manual
verified_by: ""            # заполняет человек
verified_at: ""
```

При пересборке документа vision-тракт применяет эти overrides вместо `<img>`
(приоритет: `manual` > верифицированный `vision` > `dict`). Нераспознанное
остаётся картинкой + записью в `.qa.json` (`formula_image`, номер строки,
абзац) — очередь ревью в `.qa.md` формируется конвейером уже сейчас.

## 7. Верификация и метрики

- **Golden-набор:** 30 формул СП 22 (10 целых + 20 цепочек), расшифрованных
  человеком. Метрики пайплайна считаются только по нему.
- **CER** (character error rate) против эталона: цель < 2 % для vision-формул и
  0 % для словарных после верификации словаря.
- **Покрытие:** доля формул документа в состояниях 1/3 из §2. Порог для
  `needs_review = false`: ≥ 95 % формул расшифровано.
- Жёсткое правило RAG-слоя: чанк, где формула осталась картинкой с низкой
  уверенностью, индексируется **без** псевдо-LaTeX — лучше «формула на рисунке,
  см. оригинал», чем уверенная неправда.

## 8. Порядок работы локального агента (псевдокод)

```
1. инвентаризация: собрать WMF из .assets/, sha256-дедуп, классы, контексты (§3)
2. для класса symbol:
     уникальные → PNG 600 dpi → vision-ярлык → черновик словаря
     словарь → человеку на верификацию (одноразово, дальше переиспользуется между документами!)
     собрать цепочки по контекстам → LaTeX (dict)
3. для класса formula:
     PNG → 2×vision → совпало? → обратный рендер → сверка с текстовым слоем офиц. PDF
     → yaml-override; не совпало → очередь ревью
4. пересобрать документ с overrides → lint → chunk
5. обновить .qa.md: что осталось в очереди
```

Важно: **словарь глифов — сквозной для всей базы.** Уникальные символы
КонсультантПлюс-экспорта кочуют из документа в документ; после первых 3–5
документов распознавание новых почти прекращается — остаются только целые формулы.

## 9. Риски и отказы

| риск | снижение |
|---|---|
| WMF не открывается (битый/экзотический) | фолбэк: рендер целого абзаца через LibreOffice в PDF → кроп области по координатам → vision |
| ошибка в словаре глифов (системная) | верификация словаря человеком; версионирование; прогон golden-набора при каждом изменении |
| MathJax в Obsidian не понимает диалект | ограничиться подмножеством KaTeX/MathJax; кириллица в тексте формул — только `\text{…}`; без `mhchem` (нет из коробки) |
| цепочка собралась в другом порядке (сложные дроби) | флаг `linearized_fraction`; топ-N самых цитируемых формул (видно из запросов) доводятся вручную |
| дорогая vision-модель на потоке | кэш по sha256+версия модели; сначала словарь (бесплатно), vision — только целые формулы |

## 10. Первое боевое применение: PNG-символы в PDF-экспорте (ГОСТ 27751-2014)

Механизм словаря обкатан не на WMF, а на младшем брате той же беды: экспорт СПС,
напечатанный в PDF (wkhtmltopdf), теряет картинки-символы из текстового слоя —
на их месте остаётся пробел. В ГОСТ 27751-2014 таких картинок 7: γ_f, γ_m, γ_d,
γ_n (п. 2.2.13), γ_n в шапке таблицы 2, inline-формула «γ_n =» (п. 10.1) и
надстрочный «2» в «м²» (п. Б.2).

Что сработало (и это же — шаблон для WMF-тракта):

1. **Дедупликация и провенанс по sha256** изображения: каждая картинка получила
   хэш, он записан в `правки/символы-gost-27751-2014.yaml` рядом с правилом.
2. **Опознание без vision**: независимая копия того же стандарта (PDF МЕГАНОРМ)
   держит те же символы *текстом* («коэффициенты … по нагрузке уf», «(у„= 1,2)») —
   контекстное сопоставление дало словарь; спорный знак «=» в «γ_n = 1,2»
   подтверждён именно этой копией (в экспорте СПС он выглядит как две плашки).
3. **Детерминированная подстановка**: `pdf2md --glyphs правки/символы-<doc>.yaml`
   (для docx-источников — тот же словарь через `cli convert --glyphs …`) —
   литеральные замены «дыра → символ» (`find`/`repl`), счётчик применений пишется
   в QA-отчёт; ноль применений = warning (верстка уехала, правило чинит человек).
4. **Правки переживают переконвертацию**: словарь лежит в `правки/`, а не в теле
   заметки, — стандартное правило базы «руки только через правки/».

Итог: 7 из 7 символов восстановлены, в очереди ревью по формулам для этого
документа пусто. Для WMF СП 22.13330.2016 путь тот же, но с веткой vision для
целых формул (§5–§8).
