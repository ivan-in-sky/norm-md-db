# 01 · Архитектура и формат канонического Markdown

**Финальная редакция: 2026-10-23.** Спецификация проверена на четырёх реальных
документах базы (`база/документы/`) — примеры сняты с них.

## 1. Цели формата

1. **Читаемость человеком** в любом Markdown-вьювере (GitHub, VS Code, MkDocs) без плагинов.
2. **Машиночитаемость**: каждый смысловой элемент имеет метку (пункт, таблица, формула, рисунок, примечание), по которой его можно извлечь, не «понимая» текст.
3. **Прослеживаемость**: из любого куска текста понятно, из какого источника, какой версии и с какой уверенностью он получен.
4. **Стабильность идентификаторов**: `doc_id` и номер пункта не меняются между пересборками — на них ссылаются индексы, ответы агентов и закладки пользователей.
5. **Расширяемость без миграции**: новые поля метаданных не ломают старые потребители.

## 2. Именование

```
doc_id     = <kind>-<number-slug>[-<year>]
kind       = sp | snip | gost | gost-r | rd | mds | vsn | tsn | posobie | sto | fer | gesn | ter | sn | rm | ost | tu | sanpin
number-slug= номер с заменой «.» и «/» на «-»

примеры:
  СП 63.13330.2018            → sp-63-13330-2018
  ГОСТ Р 57345-2016           → gost-r-57345-2016
  СНиП 2.01.07-85*            → snip-2-01-07-85
  РД-11-06-2007               → rd-11-06-2007
  МДС 12-29.2006              → mds-12-29-2006
```

**Два имени у каждого документа.** `doc_id` (латиница) — машинный ключ:
фронтмэттер, каталог, chunk_id, имена sidecar-файлов и ассетов. **Имя заметки**
(кириллица) — то, как документ виден человеку и Obsidian: обозначение как есть,
`СП 22.13330.2016.md`. Вики-ссылки в текстах используют беспроигрышные алиасы
(`[[СП 22.13330]]`) и резолвятся на актуальную редакцию через `aliases` +
`актуальные-версии.yaml` (см. `10-local-agent.md` §7).

Файлы (в рабочем vault `md/` = `документы/`; фактические имена — в `база/документы/`):

```
документы/<Обозначение>.md            канонический текст (имя = designation кириллицей)
документы/<Обозначение>.qa.json       отчёт о качестве (машиночитаемый)
документы/<Обозначение>.qa.md         чек-лист ручной доработки (человекочитаемый)
документы/<Обозначение>.tables.jsonl  нормализованные таблицы (по одной на строку)
документы/<Обозначение>.pages.json    привязка пунктов к страницам издания
документы/<Обозначение>.assets.json   манифест ассетов: sha256, размер, alt, тип (docx-путь)
документы/<doc_id>.assets/<doc_id>-NNN.png|wmf|svg   изображения (латиница — безопасные имена)
документы/_reports/                   dashboard.md/json + отчёты сверки <doc_id>-vs-*.md
```

Sidecar-файлы именуются **по имени заметки** (кириллица), каталог картинок —
по **doc_id** (латиница): ассеты извлекаются до того, как обозначение
распознано, и их имена должны быть переносимы между системами.

Почему рядом, а не в отдельных каталогах: документ со всеми своими производными переносится/удаляется одной операцией, `git log -- 'документы/СП 22*'` показывает всю историю, а в CI удобно проверять комплектность.

## 3. Фронтмэттер (контракт данных)

Ниже — **фактический** контракт (снят с реальной заметки `СП 56.13330.2021.md`,
значения сокращены). Порядок ключей стабилен: его задают конвертеры
(`docx2md.build_frontmatter` / `pdf2md.build_frontmatter`).

```yaml
---
# ---- идентификация ----
doc_id: sp-56-13330-2021          # стабильный машинный ключ, НЕ меняется
designation: СП 56.13330.2021     # как цитировать
kind: sp
number: 56.13330.2021
title: ПРОИЗВОДСТВЕННЫЕ ЗДАНИЯ
title_short: ""                   # заполняется через правки/ при желании
aliases:                          # механизм «ссылки не стареют» (§4.9, 10-local-agent.md §7)
  - СП 56.13330.2021              #   полное текущее
  - СП 56.13330                   #   беспроигрышное — на него ведут ссылки в текстах
  - СНиП 31-03-2001               #   заменённый документ — старая ссылка приведёт сюда
  - СНиП 31-03
note_name: СП 56.13330.2021       # имя файла заметки (кириллица)
year: 2021
issued: 27 декабря 2021 г.
title_lines: [...]                # строки титульного листа (для ручной уточнённой правки)
in_force_since: ""
issuing_body: Минстрой России

# ---- правовой и административный статус ----
status: unknown                   # active | superseded | draft | rejected | unknown | licensed
status_checked: ""                # когда сверяли с реестром (правки/<doc_id>.yaml)
supersedes: [snip-31-03-2001]     # doc_id заменённых документов
other_designations: [СНиП 31-03-2001]
superseded_by: ""
amendments: []                    # номера изменений, включённых в текст
exclusions_since: []              # даты исключений пунктов изменениями
excluded_clauses: []              # [{clause, range_to?, since, amendment}] — НЕ действующие требования
okp_okpd: ""
ics: []
topics: []
language: ru
license: официальный документ (ГК РФ ст.1259 п.6)   # лицензия к текстам нормативов неприменима (06-licenses.md)

# ---- связи и провенанс СПС ----
references: [СНиП 31-03-2001]     # упомянутые документы (versionless — в meta.refs чанков)
vendor: КонсультантПлюс           # машинный провенанс экспорта (единственное упоминание СПС в заметке)
bibliography_entries: 32
vendor_links_stripped: 144        # сколько вендорских ссылок снято очисткой

source:
  kind: docx                      # docx | doc | pdf | ocr
  file: sp_56_13330_2021.docx
  sha256: a762d300…
  uri: "https://sro-priis.ru/upload/files/snip/sp_56_13330_2021.docx"
  # необязательные (из правок/): origin_url, origin_date, publisher, text_layer

# ---- качество конвертации ----
conversion:
  tool: normconv                  # normconv | normconv.pdf2md
  version: 0.1.0
  converted_at: "2026-10-23T05:03:51+00:00"
  confidence: 0.793               # 0..1, см. Report.compute_confidence
  needs_review: true
  review_items: 19
  verified: false                 # true ставит ТОЛЬКО человек (через правки/)
  verified_by: ""
  verified_at: ""

# ---- блоки ----
blocks:
  clauses: 256                    # число пунктов с идентификаторами
  ids: 294                        # всего block id (пункты + таблицы + формулы + рисунки)
  tables:
    - {id: sp-56-13330-2021-tbl001, block_id: t1, caption: "Таблица 6.1",
       rows: 25, cols: 6, merged: true}
  figures: [{label: "Рисунок 1", caption: "…"}]
  formulas: 0
  formulas_to_review: []          # формулы с низкой уверенностью LaTeX

# ---- статистика ----
stats:
  words: 17746
  headings: {"1": 9, "2": 41, "3": 12}
  tables: 10
  formulas: 0
  images: 0
  footnotes: 0
  xrefs: "41/44"                  # разрешено / всего

# ---- страницы издания (появляется после compare pages) ----
pages_source:
  edition: "sp-56-13330-2021.pages.json"
  matched: 209
  file: СП 56.13330.2021.pages.json
---
```

Обязательные поля (отсутствие или пустота = ошибка линта): `doc_id`, `title`,
`status`, `license`; предупреждение — остальные из списка `REQUIRED_FM`
(`designation`, `kind`, `language`, `source`, `conversion`, `stats`).
Поля, которых пока нет, пишутся пустыми (`""`/`[]`) — потребители не должны
падать на их отсутствии. Схема — в `repo-template/schemas/frontmatter.schema.json`.

## 4. Разметка тела документа

Полная спецификация вынесена в **`11-markup.md`** — единый источник правды для
тела заметок: скелет документа (H1 = заголовок, H2 = разделы), пункты без
жирных номеров, формулы `$$…\tag{…}$$` + `^eNNN`, таблицы с подписью-абзацем и
`<i>/<sub>` в ячейках, рисунки с `alt`/подписью/`^fNNN` (flowchart → mermaid),
примечания-blockquote, перекрёстные ссылки `[N](файл.md#^c…)`, библиография с
`^biblio-N`, таблица block ID, запрет HTML-комментариев и алгоритм доработки
элемент за элементом. Рабочий скилл: `.agents/skills/normconv-markup/SKILL.md`.

Здесь — только три принципа, на которых всё строится:

1. **Валидный Markdown** — одинаково рендерится в Obsidian и на GitHub, без
   плагинов; HTML только там, где Markdown бессилен (`<table>` с
   `rowspan/colspan`, `<img>` с явным размером).
2. **Стабильные идентификаторы = block ID Obsidian** (`^c8-1-6`, `^t012`,
   `^e047`, `^f067`, `^biblio-2`) — одновременно валидный текст, кликабельная
   ссылка и машиночитаемый якорь. На GitHub произвольных якорей нет — точные
   строки даёт `каталог/CLAUSES.md` (ниже).
3. **Ноль «магических» комментариев** — границы элементов задают заголовки и
   block ID, а не `<!-- … -->`.

### Три слоя ссылок на пункт

Одна и та же цель («дать ссылку на п. 8.1.6») решается по-разному в зависимости от площадки — это не костыль, а следствие ограничений рендереров.

| слой | ссылка | где работает | как получается |
|---|---|---|---|
| **1. Obsidian** | `[[СП 63.13330.2018#^c8-1-6]]`; между документами — беспроигрышный алиас `[[СП 63.13330]]` (ведёт на актуальную редакцию) | Obsidian, любой редактор с поддержкой block refs | block ID в теле файла + `aliases` во фронтмэттере |
| **2. GitHub** | `…/blob/main/md/sp-63-13330-2018.md#L412` | GitHub | номер строки из генерируемого индекса |
| **3. Веб-зеркало / MCP** | `…/sp-63-13330-2018/#c8-1-6` · `norms.get(doc_id, clause)` | MkDocs/VitePress на Pages, API | плагин рендера ставит `id` на абзац пункта |

**Слой 2 подробнее.** GitHub не умеет якоря в произвольном месте `.md`, но умеет ссылку на строку файла — это работает всегда и не зависит от содержимого. Поэтому CI генерирует `catalog/CLAUSES.md`:

```markdown
| пункт | block id | строка | GitHub | Obsidian |
| --- | --- | --- | --- | --- |
| 8.1.6 | c8-1-6 | 412 | [открыть](https://github.com/org/stroy-norms/blob/main/md/sp-63-13330-2018.md#L412) | `[[sp-63-13330-2018#^c8-1-6]]` |
```

Файл перегенерируется на каждый коммит, поэтому номера строк не устаревают. Для цитирования во внешних документах используйте ссылку на **релизный тег** (`blob/v2026.10/…#L412`) — она не поедет при последующих правках.

**Слой 3** даёт «красивые» постоянные ссылки (`#c8-1-6`) — именно их стоит давать пользователям в ответах ассистента, если сайт развёрнут.

### Настройка Obsidian для работы с корпусом

- **Vault** = корень репозитория (или `md/` как отдельный vault, если корпус большой и не хочется индексировать `tools/`).
- **Settings → Files and links → Use [[Wikilinks]]** — оставить включённым для внутренних ссылок; для переносимости на GitHub дублируем ссылки в Markdown-формате там, где они в тексте.
- **Settings → Editor → Strict line breaks** — выключить, чтобы «где»-блоки и перечисления (строки подряд без пустых) рендерились как один абзац с мягкими переносами.
- **Математика** работает из коробки (MathJax); для `\text{}` с кириллицей и расширений типа `mhchem` нужен сниппет с MathJax-конфигом.
- **CSS-сниппет** (`.obsidian/snippets/norms.css`) — делает идентификаторы блоков почти незаметными при чтении и скрывает служебные строки:

```css
/* identifiers of blocks: тихий серый, не отвлекает */
.markdown-rendered p > .block-id,
.markdown-source-view.mod-cm6 .cm-blockid { opacity: .35; font-size: .8em; }

/* подписи таблиц и рисунков — как подписи, а не как обычный текст */
.markdown-rendered p:has(+ table),
.markdown-rendered p:has(+ img) { font-weight: 600; font-size: .95em; }

/* таблицы нормативов: компактно, с границами, без «разъезжающихся» шапок */
.markdown-rendered table { font-size: .9em; }
.markdown-rendered table th { background: var(--background-secondary); }
```

- **Полезные плагины** (опционально, корпус от них не зависит): *Omnisearch* (поиск по всему корпусу), *Dataview* (запросы к фронтмэттеру: «покажи все `status: superseded`»), *Advanced Tables* (ручная правка таблиц), *Linter* (форматирование).

## 5. Слои данных и их владельцы

Рабочая база — vault `база/` (русскоязычные папки); при публикации (фаза 2)
он отображается в англоязычное репо (`источники/`→`sources/`, `документы/`→`md/`,
`правки/`→`overrides/`, `каталог/`→`catalog/`, `индекс/`→`index/`).

| слой (vault) | кто пишет | кто читает | ценность |
|---|---|---|---|
| `источники/` (оригиналы + inventory.csv) | агент (скачивание) / человек | конвертер | **невозобновляемое** — хранить вечно |
| `документы/*.md` + sidecars | конвейер | все | пересобирается из источников + правок |
| `правки/` (overrides) | человек / агент через override-файлы | конвейер при пересборке | **невозобновляемое** (ручной труд) |
| `актуальные-версии.yaml` | агент (сверка реестров) + человек | конвертер, obsidian-слой | невозобновляемое (но восстанавливается сверкой) |
| `каталог/` (catalog.*, INDEX, CLAUSES) | конвейер (`catalog`, `clauses`) | люди, агенты | производное — пересобирается |
| `индекс/` (chunks.jsonl, atoms, stats) | конвейер (`chunk`) | RAG-пайплайн | кэш — пересобирается |
| эмбеддинги / векторная БД | индексатор агента | поиск | кэш — пересобирается из chunks.jsonl |

Ключевое: стрелка данных всегда идёт сверху вниз, и **ручная правка возможна
только в `правки/`**. Это единственное правило, которое удерживает систему от
деградации через год эксплуатации.
