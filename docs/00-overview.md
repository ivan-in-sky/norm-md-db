# 00 · RAG-база строительных нормативов — обзор проекта

**Финальная редакция: 2026-10-23.** Проект прошёл стадию предложения: конвейер
построен, обкатан на четырёх реальных документах, база живёт и пополняется по
регламенту. Этот файл — карта проекта и зафиксированные решения. Исполнительный
алгоритм работы — [`10-local-agent.md`](10-local-agent.md); сводка для агента —
[`../AGENTS.md`](../AGENTS.md).

## Что построено

Корпус нормативных документов строительства (СП, СНиП, ГОСТ, ГОСТ Р, РД, МДС,
ВСН, ТСН, Пособия, сметные нормативы) в виде **канонического Markdown с богатыми
метаданными** — для чтения человеком в Obsidian и для RAG-поиска агентами.

Три решения, которые определили 90% результата:

| # | Решение | как реализовано |
|---|---|---|
| 1 | **Конвертация** | собственный конвейер `normconv` поверх OOXML и PDF (~6,5 тыс. строк): QA-отчёт на каждый документ, числовая уверенность, явная очередь ручной доработки. Формулы OMML → LaTeX с confidence; таблицы со слияниями → HTML + нормализованная сетка в sidecar; нумерация пересчитывается из `numbering.xml`; вендорские артефакты справочных систем вычищаются автоматически |
| 2 | **Хранение** | рабочий Obsidian-vault `база/` (русскоязычный, self-contained): оригиналы в `источники/` + inventory.csv, заметки в `документы/`, ручные правки только в `правки/`, производные (`каталог/`, `индекс/`) пересобираются одной командой. Публикационный git-репозиторий — фаза 2, скелет готов (`repo-template/`) |
| 3 | **Доступ** | vault = источник истины. Агенты работают через каталог + указатель пунктов CLAUSES + стабильные block ID + навыки (skills). Эмбеддинги — на стороне агента из `chunks.jsonl`. MCP-сервер/сайт — фаза 2 |

## Архитектура одним взглядом

```
                 ┌──────────────── ИСТОЧНИКИ ────────────────┐
  A. PDF офиц.   │  Б. DOC/DOCX (экспорты СПС)  В. PDF/скан   │
  (ФЦС, зеркала) │                                (старые СНиП)│
        └──────────────┬──────────────────────┬───────────────┘
                       ▼                      ▼
              [1] NORMALIZE            [1'] OCR классы B/C
              .doc → .docx (LO headless)     (фаза 2, docs/09)
                       └──────────┬───────────┘
                                  ▼
                    [2] CONVERT  (normconv, детерминированно)
                    docx|pdf → канонический .md + sidecars (.qa, .tables, .pages, .assets)
                                  ▼
                    [3] ОБСИДИАН-СЛОЙ (автоматически)
                    вендор-очистка · маркеры изменений · вики-ссылки на актуальные
                    редакции через актуальные-версии.yaml · алиасы заметок
                                  ▼
                    [4] LINT + QA-ТРИАЖ + СВЕРКА С ЭТАЛОНОМ
                    errors → гейт; compare: покрытие, значения, страницы
                                  ▼
                    [5] ENRICH
                    статус действия (правки/), темы, объяснённые расхождения,
                    словарь символов (--glyphs), граф ссылок (meta.refs)
                                  ▼
                    [6] DERIVE  (всё пересобираемое)
                    catalog.* · INDEX.md · CLAUSES.* · chunks.jsonl (+atoms)
                                  ▼
                    [7] SERVE
                    Obsidian · grep · chunks.jsonl → эмбеддинги агента
                    (MCP-сервер/сайт — фаза 2)
```

## Принятые решения (вместо прежних «4 вопросов»)

Ранние редакции этого документа оставляли четыре вопроса заказчику. По итогам
работы они решены фактически и фиксируются здесь:

1. **Открытость.** База ведётся как **приватный локальный vault** (`база/`).
   Публикация — отдельная фаза 2: скелет репозитория с NOTICE/лицензиями/
   takedown-процедурой готов (`repo-template/`), публикация имеет смысл после
   накопления вычитанных документов и юридического решения (см. `06-licenses.md`,
   стратегия 1 → 2).
2. **Оригиналы.** Хранятся вместе с базой: `база/источники/` + `inventory.csv`
   (sha256, URL, дата, уровень доверия). При текущем масштабе object storage не
   нужен; при росте — вариант B из `03-storage.md` (текст в Git, бинарники в
   бакет), миграция описана.
3. **Масштаб и темп.** База пополняется **по мастер-алгоритму** (`10-local-agent.md`)
   документ за документом, приоритет — топ красных ссылок (самые цитируемые
   документы). Пакетный импорт из «тысячи файлов» не планируется: каждый
   документ проходит сверку с эталоном и QA-триаж. Ручная верификация — только
   через очередь по приоритетам, `verified` ставит человек.
4. **Поисковый бэкенд.** Текущий доступ: **файлы vault** (Obsidian, grep) +
   `индекс/chunks.jsonl` для эмбеддингов на стороне агента + `каталог/CLAUSES`
   для точного цитирования. Qdrant/pgvector, MCP-сервер и статический сайт —
   фаза 2 с явными критериями запуска (`07-roadmap.md`).

## Что можно запустить прямо сейчас

```bash
cd <корень репозитория>                            # корень git-репозитория (normconv/)
pip install lxml pillow pyyaml pymupdf pymupdf4llm   # + python-docx для теста
export PYTHONPATH=tools

# смоук-тест на синтетическом «трудном» документе
python3 tools/make_sample_docx.py /tmp/sample.docx
python3 -m normconv.cli convert /tmp/sample.docx --out /tmp/smoke --jobs 1
python3 -m normconv.cli lint /tmp/smoke              # ожидаем error: 0

# полный цикл на реальном документе — команды и рецепты: docs/10 §3, Приложение B
```

Готовые результаты смоук-теста — в [`example/`](../example/): канонический `.md`
с фронтмэттером, таблица со слияниями без фантомных столбцов, формулы в LaTeX
(confidence 1.0), сноски, рисунки, QA-отчёт, чанки с «хлебными крошками»,
каталог, указатель пунктов.

## Модули конвейера (`tools/normconv/`)

| модуль | что делает |
|---|---|
| `docx2md.py` | OOXML → канонический Markdown: таблицы (vMerge/gridSpan), поля Word (REF/PAGEREF/SEQ), сноски, рисунки, OLE, примечания, подписи, «где»-блоки, block ID, исключения пунктов изменениями |
| `omml2latex.py` | OMML → LaTeX напрямую, с оценкой уверенности и списком неизвестных конструкций |
| `pdf2md.py` | PDF с текстовым слоем → Markdown: детектор колонтитулов (в т.ч. скрытых вендорных), склейка абзацев через страницы, разряженные номера, `pages.json`, словари символов `--glyphs`, мета-override |
| `obsidian.py` | obsidian-слой: имена заметок кириллицей, алиасы, реестр версий, вендор-очистка, маркеры изменений, вики-ссылки на актуальные редакции, словарь глифов (общий с pdf2md) |
| `meta.py` | распознавание обозначения/названия/органа/года/изменений/замен/исключений, детект вендора, граф упомянутых документов |
| `ooxml.py`, `styles.py` | сетка таблицы с раскрытием слияний; карта стилей + пересчёт автонумерации из `numbering.xml` |
| `lint.py` | гейт: фронтмэттер, иерархия, пропуски нумерации, block ID, якоря, ассеты, `$$`, `<table>`, сноски |
| `compare.py` | сверка «рабочая ↔ эталон»: покрытие пунктов (с классификацией «исключено изменением» и «объяснено»), разделы, таблицы, числовые значения; перенос страниц издания |
| `chunker.py` | RAG-нарезка: пункт не режется, таблица атомарна + «атом», `meta.refs`, `doc.references`, title_page |
| `catalog.py`, `clauses.py` | производный каталог (jsonl/csv/yaml/INDEX.md) и указатель пунктов (block id → строка → ссылки Obsidian/GitHub) |
| `cli.py` | батч-конвертация с кэшем по sha256+флаги, параллелизмом и дашбордом; report/lint/chunk/catalog/clauses |
