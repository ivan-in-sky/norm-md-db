# 10 · Локальный агент: сквозной алгоритм работы с базой

> **Исполнительный ранбук. Финальная редакция от 2026-10-23.**
>
> Этот документ **самодостаточен**: в нём есть всё, что нужно агенту (с vision и
> доступом в интернет) для полного цикла ведения базы нормативов — окружение,
> форматы данных, точные команды, пороги качества, ветки отказов, точки участия
> человека. Остальные файлы `docs/` — справочники и обоснования («почему устроено
> так»); для работы они не обязательны и читаются по ссылкам отсюда.
>
> Алгоритм проверен полным циклом на четырёх реальных документах базы:
> СП 56.13330.2021 (docx-экспорт СПС + официальный PDF-эталон),
> СП 22.13330.2016 (docx-экспорт СПС с Изм. 1–5 + официальный PDF-эталон),
> ГОСТ 31937-2024 (официальный PDF с OCR-слоем как источник текста),
> ГОСТ 27751-2014 (PDF-экспорт СПС: переиздание с Изм. 1, словарь символов,
> сверка с исходным изданием). Человек в цикле — только в трёх точках:
> верификация словаря формул/символов, присвоение `verified`, подтверждение
> спорного статуса действия.

## 0. Роль агента и принципы

1. **Только актуальные редакции.** В `документы/` живёт действующая редакция с
   изменениями, включёнными в текст. Маркеры вида *(абзац введён Изменением N 5,
   утв. Приказом…)* сохраняются как нейтральный факт. Отдельных заметок-«изменений»
   база не заводит.
2. **Ссылки ведут на актуальную версию.** Вики-ссылка в тексте — беспроигрышный
   алиас: `[[ГОСТ 31937]]`, а не `[[ГОСТ 31937-2011]]`. Резолвинг — через
   `актуальные-версии.yaml` и алиасы заметок. Красная ссылка = «документ ещё не
   добавлен» — это нормальное состояние и очередь на скачивание.
3. **Никаких упоминаний справочных систем** (КонсультантПлюс, Техэксперт, Кодекс,
   cntd, Гарант) в тексте, ссылках, `alt`, примечаниях. Единственные места, где
   фиксируется происхождение файла, — поля `vendor:`/`publisher:` во фронтмэттере
   и `inventory.csv` (машинный провенанс; при публикации базы срезаются).
4. **Оригинал неприкосновенен.** `источники/` — только чтение. Все правки —
   через `правки/` (overrides), они переживают переконвертацию. Правка
   непосредственно в заметке = потеря при следующей пересборке.
5. **Официальный PDF — эталон для сверки и номеров страниц, а не источник текста**
   (исключение — путь A: когда docx нет вовсе, см. §6). У публикаций ФЦС текстовый
   слой ABBYY теряет подстрочные индексы формул (`Nγ` → `N`); текст берётся из
   `.docx`, а официальный PDF — для `compare` (покрытие) и `pages` (пагинация).
6. **Детерминизм.** Одинаковый вход + одинаковые флаги + одна версия инструмента
   ⇒ байт-в-байт одинаковый выход, кроме таймстемпа `converted_at`. Поэтому
   заметку всегда можно пересобрать и diff покажет только содержательные изменения.

## 1. Раскладка проекта и окружение

### 1.1 Каталоги

```
<корень репозитория>                  (git-репозиторий normconv/)
├── AGENTS.md                         # сводная памятка агента (читать первым)
├── README.md                        # карта проекта
├── docs/                            # эта документация (00–10)
├── tools/normconv/                  # пакет конвертера (python)
├── tools/make_sample_docx.py        # генератор синтетического теста
├── example/                         # showcase: sample.docx + полные результаты
├── repo-template/                   # скелет публикационного репо (фаза 2)
└── база/                            # рабочий Obsidian-vault (см. §2)
    └── _work/                       # рабочая зона (gitignore): эталонные извлечения официальных PDF
```

Каталоги эталонных извлечений живут в **`база/_work/`** (рабочая зона, не
коммитится): это воспроизводимые производные от PDF из `база/источники/`
(пересоздаются одной командой `pdf2md`, см. §6.4). Для нового документа
эталон кладётся в `база/_work/эталон-<doc_id>/`.

### 1.2 Зависимости

Python ≥ 3.10. Пакеты (ставятся заново после каждой свежей сессии — в песочнице
установки не переживают перезапуск; на локальной машине ставятся один раз):

```bash
pip install lxml pillow pyyaml pymupdf pymupdf4llm
# опционально:
pip install python-docx        # только для генерации синтетического теста
# LibreOffice (soffice) — для .doc → .docx и (в фазе 2) рендера WMF
```

Все команды выполняются из корня проекта с:

```bash
export PYTHONPATH=tools
```

### 1.3 Самопроверка окружения (смоук-тест)

```bash
python3 -m normconv.cli --version                          # печатает версию
python3 tools/make_sample_docx.py /tmp/sample.docx # синтетический «трудный» документ
python3 -m normconv.cli convert /tmp/sample.docx --out /tmp/smoke --jobs 1
python3 -m normconv.cli lint /tmp/smoke                    # ожидаем error: 0
```

Ожидаемый результат: конвертация ~0.1 с, confidence ≈ 0.96–0.98, lint без ошибок.
Эталонный результат лежит в `normconv/example/` — можно сверяться с ним.

## 2. Vault и форматы данных

### 2.1 Структура vault

```
база/                              ← корень Obsidian-vault
├── README.md                      # с чего начать (для человека); текущее состояние базы
├── актуальные-версии.yaml         # реестр: актуальные редакции + замены (СНиП→СП)
├── входящие/                      # inbox: только что скачанные файлы; НЕ задерживаются
├── источники/                     # оригиналы навсегда (только чтение) + inventory.csv
├── документы/                     # заметки и sidecars:
│   ├── <Обозначение>.md           #   канонический текст (имя = designation кириллицей)
│   ├── <Обозначение>.qa.json      #   QA-отчёт (машиночитаемый)
│   ├── <Обозначение>.qa.md        #   очередь ручной доработки (человекочитаемая)
│   ├── <Обозначение>.tables.jsonl #   нормализованные сетки таблиц
│   ├── <Обозначение>.pages.json   #   привязка пунктов к страницам издания
│   ├── <Обозначение>.assets.json  #   манифест картинок (docx-путь)
│   ├── <doc_id>.assets/           #   сами картинки (латиница — безопасные имена)
│   └── _reports/                  #   dashboard.md/json + отчёты сверки *-vs-*.md
├── каталог/                       # catalog.{yaml,jsonl,csv}, INDEX.md, CLAUSES.{md,jsonl}
├── индекс/                        # chunks.jsonl + chunks.atoms.jsonl + chunks.stats.json (кэш)
└── правки/                        # overrides — ЕДИНСТВЕННОЕ место ручных правок
    ├── <doc_id>.yaml              #   ручные поля фронтмэттера (мета-override)
    ├── символы-<doc_id>.yaml      #   словарь символов-картинок (глиф-правила)
    ├── сверка-<doc_id>.yaml       #   объяснённые расхождения с эталоном
    └── материалы/<doc_id>/        #   доказательства ручной верификации (кропы, листы)
```

Поток данных всегда в одну сторону:

```
входящие/ → источники/ → документы/ → каталог/ + индекс/
                ↑____________правки/ (применяются при каждой пересборке)
```

`индекс/` и `каталог/` — пересобираемый кэш: удаляются и восстанавлируются
из `документы/` в любой момент. Ценность есть только в `источники/`,
`документы/` (заметки), `правки/` и `актуальные-версии.yaml`.

### 2.2 `актуальные-версии.yaml` (реестр версий)

```yaml
версии:                       # versionless-обозначение → актуальное полное
  ГОСТ 31937: ГОСТ 31937-2024
  СП 22.13330: СП 22.13330.2016

замены:                       # смена семейства: старое обозначение → алиас новой заметки
  - старый: СНиП 2.02.01-83
    новый: СП 22.13330.2016
```

Конвертер использует реестр, чтобы вики-ссылка в тексте вела на действующую
редакцию (`[[ГОСТ 31937-2011]]` в источнике → `[[ГОСТ 31937]]` в заметке).
Пустой или неполный реестр не ломает конвертацию: неизвестная ссылка остаётся
«висячей» красной ссылкой — это сигнал «документ не добавлен».

### 2.3 `источники/inventory.csv` (провенанс)

Колонки (ровно эти 16, порядок фиксирован):

| колонка | содержание |
|---|---|
| `file` | имя файла в `источники/` |
| `sha256` | хэш файла (сразу после скачивания) |
| `size_bytes` | размер |
| `kind` | `docx` / `doc` / `pdf` / `html` |
| `doc_id` | машинный id документа (`sp-22-13330-2016`) |
| `source_level` | `A` официальный XML/UZ · `B` рабочий живой текст (docx, нативный PDF-экспорт) · `C` скан/PDF-эталон/агрегатор |
| `source_tier` | `official_publication_pdf` · `commercial_sps_export` / `sps_export` · `aggregator_pdf` / `aggregator_html` · `registered_copy_scan` |
| `text_layer` | `yes` / `yes_native` / `yes_ocr_abbyy` / `no` / `n/a` |
| `has_math_omml` | `yes` / `no` / `n/a` (для docx) |
| `has_images` | `yes` / `no` / `n/a` |
| `tables_guess` | оценка числа таблиц |
| `origin_url` | URL скачивания (**обязателен**; если потерян — пустая строка и пояснение в `notes` + задача восстановить) |
| `origin_date` | дата скачивания (ГГГГ-ММ-ДД) |
| `fetched_from_sandbox` | `yes`/`no` — скачано из ограниченной среды (влияет на доступность источников, см. Приложение A) |
| `license_note` | правовая пометка (обычно «официальный документ (ГК РФ ст.1259 п.6)» + оговорки) |
| `notes` | всё важное: редакция, изменения, ловушки (напр. «metadata.title врёт»), роль файла (источник текста / эталон / только сверка) |

Правила: одна строка на файл; файл без строки в inventory не существует для
базы; повтор того же sha256 не обрабатывается (дедупликация); файл из
`входящие/` переезжает в `источники/` под именем `<doc_id>-<происхождение>.<ext>`
(примеры: `sronoso-sp22.docx`, `faufcc-sp56.pdf`, `gost-27751-2014-fkr.pdf`).

### 2.4 `правки/` — три типа override-файлов

**(а) `<doc_id>.yaml` — ручные поля фронтмэттера.** Плоский YAML; поля
сливаются с автоматически распознанными **после** распознавания (ручное
побеждает). Поддерживаются любые поля фронтмэттера: `title`, `title_short`,
`number`, `issued`, `in_force_since`, `issuing_body`, `status`,
`status_checked`, `amendments`, `supersedes`, `supersedes_designations`
(обозначения заменённых документов — попадают в `aliases` заметки),
`superseded_by`, `topics`, `ics`, `okp_okpd`, `other_designations`,
`excluded_clauses`, `verified`, `verified_by`, `verified_at`, а также
`publisher`, `text_layer`, `origin_url`, `origin_date` (попадают в блок
`source:`). Примеры — `правки/gost-27751-2014.yaml`,
`правки/gost-31937-2024.yaml`.

**(б) `символы-<doc_id>.yaml` — словарь символов-картинок** (механизм из
`08-wmf-formulas.md`; боевой кейс — ГОСТ 27751-2014):

```yaml
- sha256: ae351aad…          # провенанс: хэш изображения, из которого взят символ
  find: "по нагрузке , коэффициенты"     # литеральный текст с «дырой» на месте картинки
  repl: "по нагрузке $\\gamma_f$, коэффициенты"   # подстановка (LaTeX/юникод)
  note: "γ_f — коэффициент надежности по нагрузке (п. 2.2.13)"
```

Применяется флагом `--glyphs`; число применений каждого правила пишется в QA.
**Ноль применений = warning** (вёрстка уехала — правило чинит человек). Словарь
верифицирует человек один раз; доказательства (кропы изображений, контактные
листы) кладутся в `правки/материалы/<doc_id>/`.

**(в) `сверка-<doc_id>.yaml` — объяснённые расхождения с эталоном.** Когда
`compare` сообщает «потерю» пункта, которая на самом деле — перенумерация
изменением или артефакт извлечения эталона, это фиксируется здесь и передаётся
флагом `--explained`; гейт сверки проходит без ручных оговорок каждый раз:

```yaml
- эталон: "12.8"             # пункт, который эталон считает существующим
  рабочая: "12.7*"           # соответствующий пункт рабочей версии (проверяется, что он есть)
  причина: >-
    Изменение N 1 (приказ Росстандарта от 23.12.2022 N 1571-ст) перенумеровало
    п. 12.8 в «12.7*»; содержание сохранено.
```

### 2.5 Имена и sidecars

- **Имя заметки** = обозначение кириллицей как есть: `СП 22.13330.2016.md`,
  `ГОСТ 27751-2014.md` (генерируется конвертером из распознанного designation,
  а не из имени файла).
- **`doc_id`** (латиница) — машинный ключ: `sp-22-13330-2016`. Используется в
  именах override-файлов, каталоге, chunk-ах, именах картинок и каталоге
  `<doc_id>.assets/`.
- Sidecar-файлы (`.qa.json`, `.qa.md`, `.tables.jsonl`, `.pages.json`,
  `.assets.json`) именуются **по имени заметки**; каталог картинок — по `doc_id`.

## 3. Мастер-алгоритм (полный цикл на один документ)

Точные команды — в §§ 4–11; здесь цикл целиком, одним блоком. Можно давать
агенту как есть.

```
ЗАДАЧА: добавить/обновить документ X в базе.

 0. КОНТЕКСТ. Прочитать база/README.md (состояние) и каталог/INDEX.md (состав).
    Если X уже в vault и sha256 источника совпадает с inventory — КОНЕЦ.
 1. РАЗВЕДКА (§4). versionless(X) → реестры ФЦС/ФГИС СТ. Действующая редакция R.
    Результат: R, статус, дата проверки, чем заменён (если X устарел).
 2. СКАЧАТЬ (§5). Приоритет: официальные → зеркала/СРО → пользовательские
    экспорты СПС. Каждый файл: sha256, валидность, строка в inventory.csv.
    Текстовый источник и PDF-эталон — разные файлы, качаются оба (если есть).
 3. ПРИНЯТЬ. входящие/ → probe (§6.1) → переименовать → источники/.
 4. СКОНВЕРТИРОВАТЬ (§6). docx | pdf(путь A) | pdf(эталон) | .doc → документы/.
    Флаги: --registry, --license «официальный документ (ГК РФ ст.1259 п.6)»,
    --source-uri; при наличии правок — --glyphs / --meta-override.
 5. ОЧИСТИТЬ (§7). Вендор-очистка автоматическая; проверить grep-ом (§7):
    упоминания СПС в теле заметки — пусто (кроме vendor:/publisher: во фронтмэттере).
 6. СВЕРИТЬ (§6.4). Эталонное извлечение → compare (гейт: rc=0, покрытие ≥ 0.95;
    потери объясняются через правки/сверка-<doc_id>.yaml --explained) →
    compare pages → pages.json. Отчёт — в документы/_reports/.
 7. ПРОВЕРИТЬ (§8). lint = 0 errors (жёсткий гейт); warnings — рабочая очередь.
    QA-триаж по <заметка>.qa.md: каждый review-тип → действие из таблицы §8.2.
 8. СТАТУС (§9). Реестр → правки/<doc_id>.yaml: status + status_checked.
    Не определяется однозначно → вопрос человеку.
 9. ЗАМЕНИТЬ старую редакцию, если была (§9.3): aliases, supersedes/
    superseded_by, реестр, CHANGELOG.
10. ПЕРЕСОБРАТЬ (§10): chunk → catalog → clauses → report; lint повторно.
11. ОТЧИТАТЬСЯ (§11): строка CHANGELOG + сводка: confidence, review_items,
    что осталось в очереди, какие красные ссылки найдены в тексте.
```

Гейты цикла (без их выполнения документ не считается добавленным):

| гейт | порог |
|---|---|
| lint | `error: 0` (warnings допустимы — это очередь задач) |
| compare с эталоном (когда эталон есть) | rc=0; покрытие пунктов ≥ 0.95; необъяснённых потерь нет |
| вендор-grep | 0 упоминаний СПС в теле |
| inventory | строка на каждый файл, sha256 и origin_url заполнены |
| производные | chunk/catalog/clauses пересобраны после любого изменения заметок |

## 4. Шаг 1 — разведка: какая редакция актуальна

Источники истины по статусам:

| вид документа | реестр | как опрашивать |
|---|---|---|
| СП (своды правил) | реестр ФАУ «ФЦС» Минстроя — `faufcc.ru` (раздел «Реестры» → своды правил) | страница реестра + `api.faufcc.ru/api/assets/<uuid>` для PDF |
| приказы об утверждении/изменениях СП | `minstroyrf.gov.ru` — раздел документов и пресс-центр | поиск по обозначению (§5.2) |
| ГОСТ / ГОСТ Р | ФГИС СТ Росстандарта — `protect.gost.ru` (`gost.ru`) | поиск по обозначению, карточка даёт статус и дату |
| СНиП (исторические) | не действуют; проверяем, чем заменены (ФЦС/meganorm как справочник) | результат — в `замены:` реестра |

Алгоритм разведки для обозначения `X`:

```
1. base = versionless(X)                       # «ГОСТ 31937-2011» → «ГОСТ 31937»
2. реестр: найти все редакции семейства base
3. выбрать действующую (статус «действует», максимальная дата введения)
4. если действующая ≠ той, что в vault:
     актуальные-версии.yaml: версии[base] = <новое обозначение>
     задача: скачать новую редакцию, старую заменить (§9.3)
5. если X — СНиП/устаревший: найти замену → замены: {старый: X, новый: Y}
6. статус + дату проверки → правки/<doc_id>.yaml (status, status_checked)
```

**Если реестр недоступен** (из песочницы `protect.gost.ru`/`minstroyrf.gov.ru`
не достигаются — см. Приложение A): статус определяется по косвенным признакам
(зеркала, ИУС, маркеры изменений в экспортах СПС), записывается с пометкой в
`notes` inventory и **остаточная сверка ставится в очередь** первой задачи на
локальной машине. `status: unknown` при этом — легальное состояние (lint даст
warning `fm_status_unknown`, не error).

Периодичность: полный прогон по каталогу — раз в неделю (изменения выходят
постоянно); внеочередной — когда в тексте найденного документа встречается
обозначение, которого нет в реестре.

## 5. Шаг 2 — скачивание файла

Приоритет источников (колонка `source_tier` в inventory):

1. **Официальные:** `api.faufcc.ru` (PDF ФЦС), `minstroyrf.gov.ru`,
   `protect.gost.ru`, `pravo.gov.ru`;
2. **Зеркала и СРО-сайты:** `meganorm.ru`, `files.stroyinf.ru`, `e-spk.ru`,
   сайты СРО (`sro-priis.ru`, `sronoso.ru`) — часто выкладывают `.docx`
   редакций, которых нет в свободном доступе у ФЦС; PDF МЕГАНОРМ по ГОСТ даёт
   **официальную пагинацию** (folio в полях) — из неё строится эталонный
   `pages.json`, когда официальная публикация недоступна;
3. **Экспорты справочных систем** (КонсультантПлюс/Техэксперт/Кодекс у
   пользователей и на сайтах-зеркалах): допустимы как источник текста, требуют
   полной вендор-очистки (§7) и пометки `vendor:`/`publisher:`. Экспорт СПС
   может быть **новее** официального издания (переиздание с включениями
   изменений) — это не дефект, а рабочая редакция; сверка с эталоном трактует
   разницу как «разницу редакций» (§6.4).

Вежливость: robots.txt, задержка 2–3 с между запросами, честный User-Agent,
без параллелизма и без обходов блокировок/пейволов.

### 5.1 api.faufcc.ru — проверенный рабочий путь

```
1. На faufcc.ru в реестре сводов правил найти документ → в карточке ссылка на
   asset: https://api.faufcc.ru/api/assets/<uuid> — прямой PDF официальной
   публикации, отдаётся без авторизации.
2. ВНИМАНИЕ: metadata.title у asset'а может врать. Реальный кейс: PDF СП 22
   отдавался с заголовком «СП 50-101-2004». Обозначение ВСЕГДА парсится из
   текста первой страницы (это делает meta.py), а не из метаданных ответа.
3. PDF ФЦС — скан с OCR-слоем ABBYY: для базы это эталон (сверка, страницы);
   как источник текста — только путь A (§6.3), когда docx нет.
```

### 5.2 minstroyrf.gov.ru — алгоритм обхода

Сайт Минстроя недружелюбен к автоматике (из песочницы недостижим вовсе;
локальный агент обычно ходит нормально):

```
1. robots.txt — прочитать и соблюдать; задержка 2–3 с, UA вида
   «normbase-bot/1.0 (+контакт)», без параллелизма.
2. Точки входа:
   a. /docs/ — поиск по обозначению («22.13330»);
   b. /press-center/news/ — приказ об изменении часто публикуется новостью + вложением;
   c. поиск по сайту: /search/?q=<обозначение>.
3. Файлы лежат в /upload/iblock/<hash>/<имя>.pdf|docx — ссылки приводить к
   абсолютным; скачивать одним GET, проверять Content-Type.
4. Типичные отказы:
   - 403/429 → увеличить паузу, UA как у браузера; не ломиться через защиту;
   - документ — приложение к приказу в виде скана регистрации (класс B из
     09-ocr-scans.md) → в OCR-ветку (фаза 2);
   - битая ссылка/404 → искать то же обозначение на faufcc.ru / зеркалалах.
5. Каждый успех → sha256 + URL + дата в inventory.csv.
```

### 5.3 Целостность и дедупликация

- sha256 считается **сразу после скачивания**, до любых преобразований;
- повтор файла с тем же sha256 не обрабатывается (но новая редакция при том же
  имени файла — другой sha256);
- PDF валидируется: открывается, страниц > 0, первая страница содержит
  ожидаемое обозначение (парсер `meta.py`);
- `.docx` валидируется: открывается zip, есть `word/document.xml`.

## 6. Шаг 3 — конвертация

### 6.1 Зондирование (probe) — определить путь до всякой работы

Отдельной команды probe нет — это 30-секундный скрипт (результат пишется в
inventory.csv, одно и то же дважды не зондируется). Запуск:
`python3 - "путь/к/файлу" <<'EOF' … EOF` (путь — аргумент после `-`):

```bash
python3 - "входящие/<файл>" <<'EOF'
import sys, zipfile, re
p = sys.argv[1] if len(sys.argv) > 1 else "входящие/файл"
if p.lower().endswith((".docx", ".doc")):
    z = zipfile.ZipFile(p)
    xml = z.read("word/document.xml").decode("utf-8", "ignore")
    print("docx: oMath=%d drawing=%d tbl=%d vMerge=%d gridSpan=%d" % (
        xml.count("<m:oMath"), xml.count("<w:drawing"), xml.count("<w:tbl"),
        xml.count("w:vMerge"), xml.count("gridSpan")))
    print("media:", len([n for n in z.namelist() if n.startswith("word/media/")]),
          "wmf:", len([n for n in z.namelist() if n.endswith(".wmf")]))
else:
    import pymupdf
    d = pymupdf.open(p)
    tot = sum(len(pg.get_text().strip()) for pg in d)
    imgs = sum(len(pg.get_images()) for pg in d)
    print("pdf: страниц=%d символов_слоя=%d изображений=%d" % (len(d), tot, imgs))
    print("класс:", "цифровой/нативный" if tot > 200*len(d) and imgs < len(d)
          else ("A: скан+слой" if tot > 200*len(d) else "B/C: чистый скан"))
EOF
```

Маршрутизация:

| вход | путь |
|---|---|
| `.docx` с живым текстом | §6.2 (normconv convert) |
| `.doc` | LibreOffice headless → `.docx` → §6.2 (`convert` умеет сам, если `soffice` в PATH) |
| PDF с качественным слоем, официальный/экспорт СПС | §6.3 (normconv pdf2md) |
| PDF-скан без слоя или с мусорным слоем (классы B/C) | OCR-конвейер `09-ocr-scans.md` — **фаза 2**, исполняется на локальной машине |
| официальный PDF при наличии docx | §6.4 — только эталон (сверка + страницы) |

### 6.2 Путь B: `.docx` → заметка

```bash
python3 -m normconv.cli convert "база/источники/<файл>.docx" \
  --out база/документы --jobs 1 \
  --license "официальный документ (ГК РФ ст.1259 п.6)" \
  --registry база/актуальные-версии.yaml \
  --source-uri "<origin_url из inventory>" \
  [--glyphs "база/правки/символы-<doc_id>.yaml"] \
  [--meta-override "база/правки/<doc_id>.yaml"] \
  [--force]
```

Что происходит автоматически: распознавание обозначения/названия/органа/года/
изменений/исключённых пунктов (`meta.py`), пересчёт автонумерации из
`numbering.xml`, таблицы со слияниями (HTML + сетка в `.tables.jsonl`),
OMML-формулы → LaTeX с confidence, «где»-блоки, сноски, перекрёстные ссылки,
исключение вендорских строк/ссылок/примечаний, маркеры изменений, вики-ссылки
на актуальные редакции, block ID `^c…/^t…/^e…/^f…/^biblio-N`, извлечение
картинок в `<doc_id>.assets/` с sha256-дедупликацией (WMF сохраняются как есть
— очередь по `08-wmf-formulas.md`).

Кэш: результат кэшируется по `sha256(источника) + hash(флагов) + версия`
в `документы/.normconv-state.json`; повторный запуск с теми же флагами ничего
не делает. Изменил override-файл → флаги те же, но содержимое правок новое →
нужен `--force` (или изменить набор флагов). **После применения правок всегда
пересобирать с `--force`.**

### 6.3 Путь A: PDF с текстовым слоем → заметка

Когда docx нет (ГОСТы ФЦС не раздаёт; официальной публикации среди доступных
источников может не быть) — рабочий текст берётся из лучшего доступного PDF:
переиздания СПС-экспорта (с изменениями, включёнными в текст) либо официального
PDF (класс A по `09-ocr-scans.md`).

```bash
python3 -m normconv.pdf2md "база/источники/<файл>.pdf" \
  --out база/документы \
  --registry база/актуальные-версии.yaml \
  --license "официальный документ (ГК РФ ст.1259 п.6)" \
  --source-uri "<origin_url>" \
  [--glyphs "база/правки/символы-<doc_id>.yaml"] \
  [--meta-override "база/правки/<doc_id>.yaml"]
```

Специфика pdf-пути: детектор повторяющихся служебных строк (скрытый колонтитул
СПС «Кодекс» на каждой странице снимается; факты «взамен …»/«применяется с …»
вынимаются в метаданные ДО удаления), склейка абзацев через разрывы страниц,
схлопывание разряженных номеров («2 . 1 . 1 6» → «2.1.16»), pipe-таблицы без
восстановления слияний (QA-флаг `table … сверить с изданием`), собственный
`pages.json` (номера страниц этого PDF; заменяется эталонной пагинацией в §6.4).

**Словарь символов** (`--glyphs`): в PDF-экспортах СПС картинки-символы
(γ_f, γ_n, «²») теряются из текстового слоя — на их месте «дыра». Словарь
восстанавливает их детерминированно (формат — §2.4б; полный алгоритм опознания
символов — `08-wmf-formulas.md` §10). **Мета-override** (`--meta-override`):
ручные поля фронтмэттера — титул, дата введения, состав изменений, publisher.

### 6.4 Эталон: извлечение, сверка, страницы

Когда есть официальный PDF (или независимая копия издания), он используется как
эталон. Три команды:

```bash
# 1) эталонное извлечение (рабочий каталог ВНЕ vault; для нового документа — эталон-<doc_id>/)
python3 -m normconv.pdf2md "база/источники/<официальный>.pdf" --out база/_work/md-official \
  --license "официальный документ (ГК РФ ст.1259 п.6)" --source-uri "<url ФЦС>"

# 2) сверка рабочей версии с эталоном (гейт)
python3 -m normconv.compare compare "база/документы/<Заметка>.md" "база/_work/md-official/<Эталон>.md" \
  [--explained "база/правки/сверка-<doc_id>.yaml"] \
  --out "база/документы/_reports/<doc_id>-vs-official.md"

# 3) перенос номеров страниц издания в рабочую заметку (pages.json + pages_source во фронтмэттере)
python3 -m normconv.compare pages "база/документы/<Заметка>.md" --from "база/_work/md-official/<Эталон>.pages.json"
```

Чтение результатов `compare`:

| секция отчёта | смысл | действие |
|---|---|---|
| **Покрытие пунктов** | доля пунктов эталона, найденных в рабочей версии | ≥ 0.95 — норма; ниже — разбираться, что потеряно |
| **Пункты, исключённые изменением** | эталон — исходное издание, рабочая — новее (Изм. N) | не потеря; проверить номер изменения и дату |
| **Потери пунктов** (rc=1) | реальная разница | каждая позиция: либо потеря текста (чинить), либо перенумерация/артефакт эталона (→ `правки/сверка-<doc_id>.yaml` + `--explained`) |
| **Пункты, не найденные в эталоне** | почти всегда дефект извлечения PDF-эталона | выборочная проверка |
| **Расхождения числовых значений** | часть — артефакты переносов/склейки единиц в PDF; часть — правки изменений | выборочная ручная сверка; найденные правки изменений — зафиксировать в `notes`/`причина` |

После `compare pages` во фронтмэттере появляется блок `pages_source:`
(edition/matched/file), а рядом с заметкой — `<Заметка>.pages.json`
(пункт → страница издания). Номера страниц привязаны к конкретному изданию:
при смене эталона перенос выполняется заново.

**Повторный перенос страниц**: `compare pages` не перезаписывает блок
`pages_source`, если он уже есть. При смене эталона блок сначала удаляется
(обычным редактированием фронтмэттера заметки — это служебное поле, не текст),
затем команда выполняется снова.

## 7. Шаг 4 — вендор-очистка (автоматическая) и её проверка

Очистка выполняется конвертером (`obsidian.py`, включена по умолчанию;
отключается только для отладки флагом `--no-obsidian`). Правила исчерпывающие:

| что в источнике | что становится в заметке |
|---|---|
| строки «Документ предоставлен системой КонсультантПлюс» и подобные | удаляются (счётчик `vendor_lines_stripped` в QA) |
| скрытый колонтитул СПС «Кодекс» в PDF: «…Применяется с… взамен…», «Страница N», «ИС «Кодекс: 6 поколение»», «Внимание! … см. ярлык „Примечания“» | повторяющиеся строки снимаются детектором колонтитулов (факты «взамен / применяется с» вынимаются в метаданные ДО удаления); «Примечание изготовителя базы данных» и «Текст сравнения … см. по ссылке» удаляются; «внесено изготовителем базы данных по тексту ИУС N 4, 2023» → «внесено по тексту ИУС N 4, 2023» |
| `(Измененная редакция, Изм. N 1)` | `*(Измененная редакция, Изменение N 1)*` — нейтральный факт |
| ссылки `login.consultant.ru` (сотни на документ) | текст ссылки сохраняется, гиперссылка убирается (`vendor_link_stripped`) |
| `alt="Консультант Плюс"` у картинок | `alt=""` (или подпись из контекста) |
| `> КонсультантПлюс: примечание. В официальном тексте документа, видимо, допущена опечатка: …` | `> [!warning] Опечатка в официальном тексте` + текст — без имени системы |
| прочая редакционная обвязка («в официальном тексте…», «текст в редакции…») | нейтральная формулировка в callout |
| `(абзац введен Изменением N 2, утв. Приказом Минстроя России от 17.12.2021 N 956/пр)` | `*(абзац введён Изменением N 2, утв. Приказом Минстроя России от 17.12.2021 N 956/пр)*` — провенанс правки остаётся (это факт документа), упоминание системы — нет |
| `Пункты 10.10–10.21 исключены с 08.01.2024` | `> [!warning] Пункты 10.10–10.21 исключены…` + `excluded_clauses` во фронтмэттере |
| упоминания других нормативов («…по ГОСТ 27751», «…СНиП 2.02.01-83*») | `[[ГОСТ 27751]]`, `[[СП 22.13330\|СНиП 2.02.01-83]]` — через реестр на актуальную версию |
| внутренние ссылки вида `P1553`, `[1530?]` | нормализуются в `#^biblio-N` / убираются (в QA) |

Проверка после конвертации (обязательная; только по заметке `.md` — файлы
`.qa.md` по назначению фиксируют факт экспорта в счётчиках провенанса):

```bash
grep -inE 'консультант|техэксперт|cntd|login\.consultant|ИС (\"|«)?Кодекс|СПС .{0,2}(Кодекс|Консультант|Техэксперт)|АО (\"|«)?(Кодекс|Техэксперт)|ярлык.{0,3}(\"|«)?Примечания|Примечание изготовителя|Документ предоставлен|Внимание! (Документ включен|О порядке применения)' \
  "база/документы/<Заметка>.md"
```

Допустимы только строки фронтмэттера `vendor:` и `publisher:` (машинный
провенанс) — всё остальное должно быть пусто. Шаблон намеренно **не** включает
голое слово «кодекс» и «гарант»: на них дают ложные срабатывания названия
законов («Градостроительный кодекс Российской Федерации») и обычные слова
(«гарантирующих»); вендорские формы («ИС «Кодекс», «АО "Кодекс"», «СПС
«Кодекс»», «ярлык "Примечания"») покрыты явно. Найдено в теле → дефект
очистки: воспроизвести минимальный пример, поправить правила в `obsidian.py`,
пересобрать с `--force`.

**Алиасы заметки** (frontmatter) — механизм, благодаря которому ссылки не
стареют:

```yaml
aliases:
  - СП 22.13330.2016      # полное текущее
  - СП 22.13330           # беспроигрышное — на него ведут ссылки в текстах
  - СНиП 2.02.01-83       # заменённый документ — старая ссылка приведёт сюда
  - СНиП 2.02.01
```

Когда выходит новая редакция (СП 22.13330.20XX), заметка переименовывается,
старое обозначение уезжает в `aliases` + реестр — и все `[[СП 22.13330]]` в
корпусе продолжают вести на актуальный текст без единой ручной правки ссылок.

## 8. Шаг 5 — проверки

### 8.1 lint (жёсткий гейт)

```bash
python3 -m normconv.cli lint база/документы     # код возврата 1 при errors
```

| код | уровень | смысл → действие |
|---|---|---|
| `unreadable` | error | файл не читается → переконвертировать |
| отсутствует `doc_id`/`title`/`status`/`license` | error | контракт фронтмэттера сломан → meta-override |
| `unresolved_xref` | error | неразрешённый плейсхолдер ссылки → правка конвертера/override |
| `duplicate_block_id` | error | `^id` дважды → в документе дублируются номера пунктов; проверить источник |
| `bad_block_id` | error | в ID не-латиница → баг генерации |
| `missing_asset` | error | `<img>` указывает на отсутствующий файл → пересобрать ассеты |
| `table_unbalanced` | error | `<table>`/`</table>` не сбалансированы → дефект конвертации таблицы |
| `math_unbalanced` | error | нечётное число `$$` → формула разорвана |
| `footnote_undefined` | error | `[^fn]` без определения → экспорт СПС вырезал сноски; зафиксировать в QA/notes |
| `fm_status_unknown` | warning | статус не сверен с реестром → §9 (штатная очередь) |
| `low_confidence` | warning | confidence < 0.9 → §8.2 триаж |
| `numbering` | warning | пропуск/дубль номеров пунктов → почти всегда потерянный абзац или артефакт источника; сверить с эталоном |
| `heading_skip` / `heading_too_long` / `duplicate_anchor` | warning | структура заголовков → обычно артефакт источника, выборочно |
| `tr_multiline` / `td_unbalanced` | warning | строка таблицы не на одной строке → чинится пересборкой |
| `broken_block_ref` / `broken_anchor` / `broken_file_link` | warning | битая внутренняя ссылка → проверить цель |
| `dangling_reference` | warning | «(в | по | см.) .» — потерянная ссылка экспорта СПС → в notes |
| `many_empty_paragraphs` | warning | >50% пустых абзацев — артефакт вёрстки/«PDF в doc» |
| `control_chars` | warning | непечатаемые символы |
| `glyph_substitution` (0 замен) | warning | правило словаря символов не сработало → верстка уехала, правило чинит человек |
| `vendor_footnote_markers` | warning | маркеры сносок `<*>` без текста (экспорт СПС) — смириться, факт в notes |
| `todo`, `no_h1`, `footnote_unused`, `math_empty_block`, `obsidian_block_ref` | info | информационные |

Полный фактический список — в выводе `lint -v`. Штатный warnings-набор базы:
`fm_status_unknown` (пока статусы не сверены с ФГИС/ФЦС) и `low_confidence`
(документы в очереди ручной доработки).

### 8.2 QA-триаж по `<заметка>.qa.md`

| тип review | что делать |
|---|---|
| `formula_image`, WMF/`<img>`-формулы | план `08-wmf-formulas.md`: инвентаризация → словарь глифов (человек верифицирует) → vision для целых формул (фаза 2, локальная машина) |

## 9. Шаг 6 — статус, версии, замена редакции

### 9.1 Фиксация статуса

После сверки с реестром (§4) создать/дополнить `правки/<doc_id>.yaml`:

```yaml
status: active                  # active | superseded | draft | rejected | licensed
status_checked: "2026-10-23"    # дата сверки
```

Затем пересобрать заметку с `--force` и `--meta-override` (§6.2/§6.3).
`verified: true` + `verified_by` + `verified_at` в тот же файл ставит **только
человек** после вычитки (§8.2 + чек-лист верификации в `CONTRIBUTING`).

### 9.2 Красные ссылки — очередь пополнения

После каждой конвертации собрать новые красные ссылки (вики-ссылки, у которых
нет цели в vault): в Obsidian — панель «Unlinked/Красные ссылки»; машинно —
по `catalog/INDEX.md` и grep-ом `[[…]]` по заметкам с последующей проверкой
алиасов. Топ красных ссылок = приоритетная очередь шага 1 следующего цикла
(текущий топ — в `база/README.md`).

### 9.3 Замена редакции (вышла новая версия документа в vault)

```
1. Скачать и сконвертировать новую редакцию R2 (§§ 5–8) — она приходит как
   обычная новая заметка.
2. актуальные-версии.yaml: версии[<base>] = <R2>.
3. Старую заметку R1 убрать из документы/ (архив — в git-истории; при работе
   без git — переложить в источники/архив-заметок/ с пометкой в inventory).
4. Обозначение R1 добавить в aliases заметки R2 (через supersedes_designations
   автоматически, либо meta-override other_designations) + supersedes: [<doc_id R1>].
5. Если R1 заменён ДРУГИМ документом (отменён): в заметке-преемнике
   supersedes + alias; в реестре — замены: {старый: R1, новый: R2}.
6. Пересобрать производные (§10): все [[<base>]] в корпусе теперь ведут на R2.
7. CHANGELOG: «R1 → R2: основание (приказ/дата), что изменилось содержательно».
```

## 10. Шаг 7 — производные (порядок обязателен)

```bash
python3 -m normconv.cli chunk   база/документы --out база/индекс/chunks.jsonl
python3 -m normconv.cli catalog база/документы --out база/каталог
python3 -m normconv.cli clauses база/документы --out база/каталог/CLAUSES.md
python3 -m normconv.cli report  база/документы          # → документы/_reports/dashboard.{md,json}
python3 -m normconv.cli lint    база/документы          # финальный гейт: error: 0
```

Выходы:

- `индекс/chunks.jsonl` — чанки (пункт не режется; таблица атомарна + «атом» в
  `chunks.atoms.jsonl`; «хлебные крошки» в `text`; `meta.refs` — versionless-
  обозначения, упомянутые в чанке; `doc.references` — агрегированный граф);
  сводка в `chunks.stats.json`;
- `каталог/catalog.{yaml,jsonl,csv}` + `INDEX.md` — состав корпуса, статусы,
  confidence, раздел «Требует внимания»;
- `каталог/CLAUSES.md` + `CLAUSES.jsonl` — указатель «пункт → block id → номер
  строки → ссылки (Obsidian/GitHub)»; используется для точного цитирования и
  retrieval-расширения по графу;
- `документы/_reports/dashboard.md` — очередь ручной доработки по возрастанию
  confidence + счётчики типов review.

Эмбеддинги — на стороне агента (в vault не хранятся). Payload-фильтры
обязательны: `status`, `kind`, `year`, `confidence`, `excluded_clauses`
(правила — `04-rag.md` §3). Чанк с `kind: title_page` в эмбеддинги не идёт.

## 11. Шаг 8 — отчётность

1. **CHANGELOG базы** (вести в `база/README.md` или отдельном файле): строка на

## 12. Ветки отказов (playbook)

| симптом | диагноз | действие |
|---|---|---|
| `ModuleNotFoundError` при запуске | свежая сессия, пакеты не пережили перезапуск | переустановить §1.2, повторить |
| источник недоступен (403/429/таймаут) | защита сайта или ограничения среды | сменить tier (§5): зеркала → СРО → пользовательский экспорт; записать в notes inventory; НЕ обходить защиту |
| `metadata.title` API не совпадает с текстом | известная ловушка api.faufcc.ru | доверять тексту первой страницы (meta.py так и делает); факт — в notes |
| designation распознался неверно (взялся из «взамен …») | скрытый вендорный колонтитул или мусор титула | `--meta-override` с правильными `title`/`number`; для PDF проверить, что детектор колонтитулов снял строки (QA `running_lines_stripped`) |
| compare: покрытие < 0.95 | потеря текста ИЛИ эталон другой редакции ИЛИ дефект извлечения | сверить список потерь: исключённые изменением — ок; перенумерации — в `сверка-<doc_id>.yaml`; реальные потери — искать другой источник текста |
| compare: расхождения числовых значений | артефакты переносов в PDF ИЛИ правки изменений | выборочная ручная сверка 10–20 значений; правки изменений — зафиксировать в notes/причина |
| lint `numbering` (пропуск пунктов) | потерянный абзац или артефакт нумерации источника | сверить пропуск с эталоном; в тексте СПС-экспорта пропуск часто означает «исключён изменением» — оформить callout + excluded_clauses |
| `glyph_substitution: замен 0` | правило словаря не совпало с текстом | найти актуальный литерал в заметке (вёрстка могла уйти), обновить `find` в словаре; sha256 не менять |
| WMF-картинки в заметке (`<img …wmf>`) | экспорт СПС без OMML | штатно: очередь `08-wmf-formulas.md` (фаза 2, локальная машина с LibreOffice+vision); в ответе RAG не цитировать формулы этого документа |
| PDF без текстового слоя (класс B/C) | чистый скан | OCR-конвейер `09-ocr-scans.md` — фаза 2; до тех пор документ не добавляется (либо добавляется по другому источнику) |
| `soffice` не найден при .doc | LibreOffice не установлен | установить; до установки .doc не конвертируется (конвертер честно вернёт ошибку) |
| статус не определяется (реестр недоступен) | ограничения среды | `status: unknown` + очередь на локальную сверку; в ответах RAG — оговорка «статус не сверен» |
| заметка переименовалась при пересборке | изменилось распознавание designation | старое имя удалить, ссылки-алиасы проверить; переименование — только через реестр/aliases (§9.3) |
| ручная правка потерялась после пересборки | правили заметку напрямую | восстановить из `правки/`; правило базы: руки — только через overrides |

## 13. Обслуживание базы (регулярный цикл)

- **Еженедельно:** прогон §4 по всему каталогу (новые изменения/редакции);
  найденное — в задачи на скачивание; верх красных ссылок — в задачи на добавление.
- **При обновлении:** новая редакция заменяет заметку (§9.3); реестр и
  CHANGELOG обновляются.
- **Обратная связь:** пользователь нашёл ошибку → `правки/<doc_id>.yaml`
  (или словарный файл) + пересборка с `--force`; оригинал не трогается.
- **Индекс — кэш:** `индекс/` и векторная БД пересобираются из `документы/`
  в любой момент; ничего ценного там не хранится.
- **Регрессии инструмента:** после любых изменений в `tools/normconv/` —
  смоук-тест (§1.3) + пересборка одной заметки и diff (ожидание: только
  `converted_at`).

## 14. Красные линии

- База **не является официальным изданием** — дисклеймер в README/NOTICE
  обязателен; оформление, обложки и знак © официальных изданий не
  воспроизводятся (`06-licenses.md`).
- Статус документа указывается в каждом ответе RAG-слоя; отменённый документ
  по умолчанию не цитируется; `status: unknown` цитируется с оговоркой.
- Вежливость к источникам: robots.txt, паузы, никаких обходов блокировок и
  пейволов.
- `verified` присваивает только человек. Агент готовит очередь и факты.
- Формула, оставшаяся картинкой, индексируется **без** псевдо-LaTeX: лучше
  «формула на рисунке, см. оригинал», чем уверенная неправда.
