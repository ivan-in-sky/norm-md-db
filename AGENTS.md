# AGENTS.md — памятка агента, работающего с этой базой

> Сводная точка входа (внутренний файл, не публикуется; образец — `AGENTS.md.sample`).
> Полный исполнительный ранбук — [`.dev/runbook.md`](.dev/runbook.md) (окружение, форматы,
> команды, пороги, ветки отказов). Состояние базы — в `data/README.md` и каталоге; здесь не дублируется.

## Что это

База действующих редакций строительных нормативов (СП, СНиП, ГОСТ, ГОСТ Р, РД…)
в каноническом Markdown для **Obsidian + RAG**. Не юридический продукт и **не
официальное издание**. Язык базы и общения — русский.

## Где что лежит

| путь | что |
|---|---|
| `data/` | документы: `<категория>/<ОБЗ>/<ОБЗ>.md` + `assets/`; `registry.yaml`, `inventory.csv` |
| `.sources/` | исходники PDF/DOCX (не в git) — **только чтение** |
| `tools/normconv/` | конвертер: docx2md, pdf2md, obsidian-слой, meta, lint, chunker, catalog, clauses, compare |
| `tools/config/` | правки: мета-override `<doc_id>.yaml`, словари символов, объяснённые сверки |
| `docs/format.md` | **контракт формата данных** (спецификация .md) — публичный документ |
| `.dev/runbook.md` | исполнительный ранбук; `.dev/conversion-notes.md` — элементы конвертации; `.dev/rag.md`, `.dev/legal.md`, `.dev/roadmap.md` |
| `CATALOG.md` | каталог (генерируется: `make catalog`) |

## Золотые правила

1. **Только актуальные редакции**, изменения включены в текст; отдельные заметки-«изменения» не заводятся. Маркеры *(абзац введён Изменением N …)* — нейтральный факт, сохраняются.
2. **Ссылки — беспроигрышные алиасы**: `[[ГОСТ 31937]]`, не `[[ГОСТ 31937-2011]]`. Резолвинг — `data/registry.yaml` + `aliases:` заметок. Красная ссылка = очередь на скачивание, это нормально.
3. **Никаких упоминаний справочных систем** (КонсультантПлюс/Техэксперт/Кодекс/cntd/Гарант) в тексте заметок. Провенанс — только `vendor:`/`publisher:` во фронтмэттере и `data/inventory.csv`. Проверка по заметке:
   `grep -inE 'консультант|техэксперт|cntd|login\.consultant|ИС (\"|«)?Кодекс|СПС .{0,2}(Кодекс|Консультант|Техэксперт)|АО (\"|«)?(Кодекс|Техэксперт)' <заметка>.md` → допустимы только строки фронтмэттера.
4. **Оригиналы неприкосновенны** (`.sources/` — только чтение). Ручные правки — **только** через `tools/config/`; правка в заметке напрямую будет затёрта пересборкой.
5. **Официальный PDF — эталон для сверки и страниц**, не источник текста (ABBYY теряет индексы формул). Исключение: текстовый исходник отсутствует вовсе.
6. **`verified` ставит только человек.** Агент готовит факты и очередь.
7. **Детерминизм**: пересборка того же источника с теми же флагами меняет только `converted_at`. После изменения `tools/config/` — пересобирать с `--force`.

## Цикл на один документ (сжато; детали — .dev/runbook.md)

```
разведка (действующая редакция, статус)
→ скачать в .sources/ (sha256 + строка в data/inventory.csv)
→ convert → lint (error: 0) → эталонная сверка с официальным PDF (compare compare/pages)
→ QA-триаж; производные (порядок фиксирован): chunk → catalog → clauses → report
```

## Пороги и гейты

| проверка | норма |
|---|---|
| `lint` | `error: 0`; штатные warnings: `fm_status_unknown`, `low_confidence` |
| сверка с эталоном | rc=0, покрытие пунктов ≥ 95 %; потери — только объяснённые (`--explained`) или исключённые изменением |
| confidence | ≥ 0.95 зелёный; < 0.8 обязательный триаж (что в review и почему) |
| вендор-grep | пусто в теле заметок |

## Формат заметки (минимум; спецификация — docs/format.md)

- имя папки/заметки = обозначение кириллицей (`СП 22.13330.2016`); `doc_id` — латиница;
- заголовки: H1 = заголовок документа, H2 = разделы/приложения, H3 = x.y;
- пункт: `8.1.6 текст… ^c8-1-6` (номер **не** жирный); таблица `^t…`, формула `^e…`, рисунок `^f…`;
- символы в тексте — только LaTeX; внутри HTML-таблиц — `<i>/<sub>` + юникод;
- примечания — `>`-цитаты; исключённые пункты — warning + `excluded_clauses` во фронтмэттере.

## Точки участия человека

1. верификация словаря формул/символов (ошибка в словаре системна);
2. присвоение `verified` (+ `verified_by/at`) после вычитки;
3. подтверждение спорного статуса действия документа.
