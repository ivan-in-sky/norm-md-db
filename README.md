# normconv — база строительных нормативов: конвейер и документация

**Финальная редакция: 2026-10-23.** Это рабочий инструмент и комплект
исполнительной документации для базы действующих редакций строительных
нормативов (СП, СНиП, ГОСТ, ГОСТ Р, РД, МДС, ВСН, сметные нормативы) в
каноническом Markdown — для **Obsidian + RAG**. Конвейер построен, обкатан
полным циклом на четырёх реальных документах и эксплуатируется; рабочая база —
vault [`база/`](база/).

## Быстрый старт

```bash
cd <корень репозитория>                            # корень git-репозитория (normconv/)
pip install lxml pillow pyyaml pymupdf pymupdf4llm   # + python-docx для теста ниже

export PYTHONPATH=tools
python3 -m normconv.cli --version                    # самопроверка

# смоук-тест на синтетическом «трудном» документе:
python3 tools/make_sample_docx.py /tmp/sample.docx
python3 -m normconv.cli convert /tmp/sample.docx --out /tmp/smoke --jobs 1
python3 -m normconv.cli lint /tmp/smoke              # ожидаем error: 0
```

Готовые результаты смоук-теста — в [`example/`](example/): канонический `.md`
с фронтмэттером, таблица 4×4 с `rowspan/colspan` без фантомных столбцов,
формулы в LaTeX (confidence 1.0), сноски, рисунки, QA-отчёт, чанки с
«хлебными крошками», каталог, указатель пунктов.

Полный цикл на реальном документе (разведка → скачивание → конвертация →
вендор-очистка → сверка с эталоном → lint/QA → статус → производные → отчёт) —
**`docs/10-local-agent.md`**, точные команды с флагами и рецепты четырёх
документов базы — Приложение B.

## Что умеет конвейер (реализовано и проверено)

| задача | реализация | модуль |
|---|---|---|
| формулы OMML → LaTeX | собственный конвертер с **оценкой уверенности** и списком неизвестных конструкций | `omml2latex.py` |
| таблицы с объединёнными ячейками | сетка с раскрытием `gridSpan`/`vMerge` → HTML `rowspan/colspan` + нормализованная сетка в JSONL | `ooxml.py`, `docx2md.py` |
| нумерация пунктов и разделов | пересчёт автонумерации из `numbering.xml` + сверка с ручными номерами | `styles.py` |
| PDF с текстовым слоем → Markdown | детектор колонтитулов (в т.ч. скрытых вендорных, с markdown-обвязкой и разрывами тире), склейка абзацев через страницы, разряженные номера, `pages.json` | `pdf2md.py` |
| obsidian-слой | имена заметок кириллицей, алиасы, реестр версий, вики-ссылки на актуальные редакции, полная вендор-очистка, маркеры изменений | `obsidian.py` |
| словарь символов-картинок | `--glyphs`: детерминированные подстановки «дыр» PDF-экспортов, провенанс по sha256, счётчик в QA (обкатан: ГОСТ 27751 — 7/7 символов) | `obsidian.py`, `pdf2md.py`, `docx2md.py` |
| ручные правки (overrides) | `--meta-override` (любые поля фронтмэттера, в т.ч. `status`/`verified`), `--explained` (объяснённые расхождения сверки); всё — из `правки/`, переживает переконвертацию | `docx2md.py`, `pdf2md.py`, `compare.py` |
| метаданные | распознавание обозначения, вида, органа, года, изменений, исключённых пунктов, графа ссылок, детект вендора | `meta.py` |
| перекрёстные ссылки | двухпроходная конвертация: закладки → block ID → `[3.1.2 …](#^c3-1-2)` | `docx2md.py` |
| контроль качества | QA-отчёт на документ (`.qa.json` + `.qa.md`), confidence, чек-лист доработки, дашборд корпуса | `docx2md.Report`, `cli.py` |
| линт | фронтмэттер, иерархия, **пропуски нумерации**, block ID, якоря, ассеты, `$$`, `<table>`, сноски (гейт `error: 0`) | `lint.py` |
| эталон-сверка | покрытие пунктов (с классификацией «исключено изменением» / «объяснено»), разделы, таблицы, числовые значения, вердикт + код возврата; перенос пагинации издания | `compare.py` |
| RAG-чанкинг | пункт не режется, таблица атомарна + «атом», breadcrumb, `meta.refs`, `doc.references`, title_page | `chunker.py` |
| каталог и указатель | `catalog.{yaml,jsonl,csv}` + `INDEX.md` («Требует внимания»); `CLAUSES.{md,jsonl}`: пункт → block id → строка → ссылки | `catalog.py`, `clauses.py` |
| батч | кэш по sha256+флаги+версия, параллелизм, `.doc → .docx` через LibreOffice, сводный дашборд | `cli.py` |

Четыре документа прошли полный цикл (рецепты — `docs/10-local-agent.md`
Приложение B; состояние — `база/README.md`):

| документ | источник текста | эталон-сверка | примечание |
|---|---|---|---|
| СП 56.13330.2021 | docx-экспорт СПС (conf 0.79) | официальный PDF ФЦС: **100%** (211/211), страницы 211/235 | вендор-очистка: 144 ссылки сняты, примечание СПС во вложенной таблице обезличено |
| СП 22.13330.2016 | docx-экспорт СПС с Изм. 1–5 (conf 0.27) | официальный PDF ФЦС (исходная ред. 2016): **98,3%**, 11 пунктов классифицированы как исключённые изменениями; страницы 624/671 | экспорт СПС **новее** официального издания; 740 WMF-картинок — очередь `docs/08` (фаза 2) |
| ГОСТ 31937-2024 | официальный PDF с OCR-слоем, путь A (conf 0.816) | — (сам является официальным изданием) | колонтитулы сняты детектором (H1: 94 → 62); алиасы `ГОСТ 31937` и `ГОСТ 31937-2011` — ссылки на старую редакцию ведут на действующую |
| ГОСТ 27751-2014 | PDF-экспорт СПС «Кодекс»: переиздание с Изм. 1 (conf 0.94) | исходное издание 2014 (МЕГАНОРМ): **99,0%**, 1 расхождение объяснено (12.8 → «12.7*» перенумерацией Изм. 1); страницы 100/135 (официальная пагинация) | 7/7 символов-картинок восстановлены словарём `--glyphs`; скрытый вендорный колонтитул и выходная строка «подготовлена АО "Кодекс"» сняты |

Ключевой вывод, который лёг в архитектуру: **официальный PDF используется как
эталон для сверки и источник номеров страниц, а не как источник канонического
текста** (`docs/02-conversion.md` §9.1); исключение — путь A, когда другого
источника нет (ГОСТ 31937-2024).

## Готовый скелет публикационного репозитория (фаза 2)

[`repo-template/`](repo-template/) — копируется целиком как основа публичного
репо, когда база дорастёт до публикации (критерии — `docs/07-roadmap.md` §3):

```
repo-template/
├── README.md            # с дисклеймером, статусами документов, takedown
├── NOTICE.md            # правовой статус текстов (с судебной практикой)
├── LICENSE / LICENSE-data   # MIT (код) / CC0 (данные) + CC BY 4.0 (документация)
├── AGENTS.md            # правила для агентов: что нельзя трогать, как искать, как цитировать
├── CONTRIBUTING.md      # 3 способа помочь; верификация; правки только через overrides
├── SECURITY.md          # P1-ошибки в требованиях, takedown, уязвимости конвертера
├── Makefile             # convert / lint / chunk / catalog / clauses / report / eval / check
├── pyproject.toml
├── актуальные-версии.yaml   # копия реестра vault
├── skills/              # 6 навыков для агентов
│   ├── norms-search/  norms-citation/  norms-currency/
│   ├── norms-compliance-check/  norms-tables/  add-document/
├── schemas/             # JSON Schema: frontmatter, chunk, overrides
├── overrides/           # единственное место ручных правок (+ пример)
├── evals/qa.example.yaml
└── .github/workflows/   # convert.yml (авто-PR из inbox), quality.yml (lint + golden + evals)
```

## Ключевые решения, которые заложены в архитектуру

1. **Канонический Markdown — единственный источник истины.** Каталог, чанки,
   векторы, сайт — пересобираемые производные, как данные не хранятся.
2. **Ручные правки — только в `правки/`** (в публикации — `overrides/`).
   Иначе следующая конвертация затрёт вычитку. Три типа override-файлов:
   мета-поля, словарь символов, объяснённые расхождения сверки.
3. **Каждый документ имеет `confidence` и чек-лист доработки.** Пакетная
   конвертация без триажа = тихие ошибки в ответах агента.
4. **`^c8-1-6` — block ID Obsidian как стабильный ID пункта.** Чистый Markdown
   без HTML-комментариев: в Obsidian это кликабельная ссылка, на GitHub —
   обычный текст, для конвейера — граница чанка и ключ индекса.
5. **Ссылки — беспроигрышные алиасы** (`[[ГОСТ 31937]]`): выход новой редакции
   не рвёт ни одной ссылки в корпусе (реестр + aliases заметок).
6. **Статус действия документа — обязательное поле каждого чанка.**
   Цитирование отменённого СНиП — не «неточность», а опасная рекомендация.
7. **Официальный PDF — эталон, а не источник текста** (ABBYY теряет индексы
   формул); исключение — путь A, когда docx нет.
8. **Юридически чисто:** только тексты (ст. 1259 п.6 ГК РФ), без сканов и
   обложек; `license: официальный документ (ГК РФ ст.1259 п.6)`; вендор-очистка
   тотальная; NOTICE + takedown готовы к публикации.

## Чего нет (фаза 2 — спроектировано, не реализовано)

Критерии запуска каждого пункта — `docs/07-roadmap.md` §3:

1. vision-тракт WMF-формул (LibreOffice + vision, `docs/08`) — первый
   потребитель: СП 22.13330.2016 (740 позиций в очереди);
2. OCR сканов классов B/C (`docs/09`);
3. публикация корпуса (Git + CI + релизы) по `repo-template/`;
4. MCP-сервер `norms.search/get/status/cite`, Qdrant/pgvector, статический сайт;
5. evals-харнесс (150+ вопросов с эталонами);
6. адаптер официального XML/UZ (`uz2md`);
7. Snakemake-оркестрация (при корпусе > 1000 документов);
8. экспорт больших таблиц в CSV с усечением в Markdown.
