# Вклад в базу

## Что принимается

- **Действующие редакции** нормативных документов: изменения уже включены в текст;
  отдельные заметки «изменения N» не заводятся, пометы — нейтральные факты.
- Один документ = одна папка `data/<категория>/<ОБЗ>/` с `<ОБЗ>.md` + `assets/`.

## Цикл добавления документа (сжато)

```bash
# 1. скачать исходник в .sources/ (sha256 + строка в data/inventory.csv)
# 2. конвертация:
PYTHONPATH=tools python -m normconv.cli convert <файл> --out data \
  --license "официальный документ (ГК РФ ст.1259 п.6)" \
  --registry data/registry.yaml --source-uri <url> [--force]

# 3. эталонная сверка с официальным PDF:
PYTHONPATH=tools python -m normconv.pdf2md <офиц.pdf> --out .tmp/ref
PYTHONPATH=tools python -m normconv.cli compare compare data/<кат>/<ОБЗ>/.md .tmp/ref/*.md

# 4. гейт:
PYTHONPATH=tools python -m normconv.cli lint data          # → error: 0

# 5. производные (порядок фиксирован):
make chunk catalog clauses report
```

Полный цикл с порогами и ветками отказов — в локальном `AGENTS.md` / `.dev/runbook.md`.

## Правила качества

| проверка | норма |
|---|---|
| `lint` | `error: 0`; штатные warnings: `fm_status_unknown`, `low_confidence` |
| сверка с эталоном | покрытие пунктов ≥ 95 %; потери — только объяснённые |
| confidence фронтмэттера | ≥ 0.95 зелёный; < 0.8 — обязательный триаж (`<doc_id>.qa.md`) |
| строки справочных систем (КонсультантПлюс/Техэксперт/cntd) | **не допускаются** в теле заметок |

## Точки участия человека

1. верификация словаря формул и символов;
2. присвоение `verified: true` (+ `verified_by/at`) после вычитки — **агент не ставит**;
3. подтверждение спорного статуса действия документа (`status:`).

## Формат

Все правила разметки — [`docs/format.md`](docs/format.md). Коротко: блок-ID у каждого
элемента, формулы LaTeX, таблицы inline (HTML при слияниях), ссылки без года,
никаких HTML-комментариев и жирных номеров пунктов.
